## 対象範囲

mism は、Minecraft のサーバーを管理するためのコマンドラインツールである。
この仕様書は、mism の機能のうち、サーバーの新規作成、Minecraft のバージョンの列挙、mism がダウンロードした jar ファイルの再利用のための保存、サーバーの新規作成に伴う利用者の EULA への同意、プラグインの管理、データパックの管理と、mism 自身の出力の規則を定める。
mism が扱うサーバーは、PaperMC が配布している Paper と Folia である。
mism は、Linux の上で動く。

この仕様書の番号付きの文には、節の略号と連番からなる番号 (e.g. `new-3`)が付いている。
各テスト関数は、確かめる番号付きの文の番号を、そのテスト関数の `///` コメントに書く。

PaperMC は、Minecraft の各バージョン (e.g. `26.3`、`1.21.11`)に対して、Paper と Folia を配布している。
PaperMC は、1 つの Minecraft のバージョンに対する Paper (または Folia)に、番号で表したバージョン (e.g. `206`)を付け、そのバージョンごとに jar ファイルを配布している。
PaperMC は、Minecraft の各バージョンに、サポート状態 (SUPPORTED、DEPRECATED、UNSUPPORTED のいずれか)を付けて公開している。

## コマンドラインの形式

mism は、次のサブコマンドを持つ。

```
mism new <paper|folia> <パス> [--version <Minecraft のバージョン>]
mism versions <paper|folia>
mism plugin search <語> [--limit <件数>]
mism plugin versions modrinth:<識別子>
mism plugin fetch <取得元の指定> [--yes]
mism plugin inspect <取得元の指定> [--yes]
mism plugin place <取得元の指定>
mism plugin install <取得元の指定> [--lazy] [--yes]
mism plugin list [--global]
mism plugin remove <プラグインの名前>
mism datapack search <語> [--limit <件数>]
mism datapack versions modrinth:<識別子>
mism datapack fetch <取得元の指定> [--yes]
mism datapack inspect <取得元の指定> [--yes]
mism datapack place <取得元の指定>
mism datapack install <取得元の指定> [--lazy] [--yes]
mism datapack list [--global]
mism datapack remove <データパックの名前>
```

利用者は、Paper を `paper` という文字列で、Folia を `folia` という文字列で指定する。

- cli-1. 利用者が `mism --help` を実行したとき、mism は、mism の使い方を標準出力に出力し、終了ステータス 0 で終了する。
- cli-2. 利用者が `mism --version` を実行したとき、mism は、mism 自身のバージョンを標準出力に出力し、終了ステータス 0 で終了する。
- cli-3. 利用者が `mism new --help`、`mism versions --help`、`mism plugin --help`、`mism datapack --help`、または `mism plugin` か `mism datapack` のサブコマンド (e.g. `mism plugin search`)に `--help` を付けて実行したとき、mism は、そのサブコマンドの使い方を標準出力に出力し、終了ステータス 0 で終了する。
- cli-4. 利用者が上の形式に合わない引数を与えたとき、mism は、mism の使い方を標準エラー出力に出力し、終了ステータス 2 で終了する。
- cli-5. 利用者が <paper|folia> の位置に `paper` と `folia` 以外の文字列を与えたとき、mism は、cli-4 と同じ動作をする。

## 出力の規則

この節は、すべてのサブコマンドに共通する、mism の出力の規則を定める。
mism の出力は人向けであり、mism は、人向けの出力を標準出力と標準エラー出力に分けない。
mism は、結果を JSON で出力するオプション (`--json`)をまだ持たない。変更を行う者がそのオプションを mism に足すとき、変更を行う者は、機械向けの出力の規則をこの節に足す。

- out-1. mism 自身が標準出力に出力する文字列の各行は、`mism: ` で始まる。cli-1 から cli-4 が定める使い方の出力と、cli-2 が定める mism 自身のバージョンの出力と、out-2 の空行は、この文の対象外である。
- out-2. mism が外部のソフトウェア (e.g. サーバー)を起動してその出力を利用者に見せるとき、mism は、標準出力に、何の出力が続くかを伝える `mism: ` で始まる 1 行の文字列 (e.g. `mism: output of paper-26.3-206.jar follows`)、空行 1 行、その外部のソフトウェアの標準出力と標準エラー出力の内容 (mism は、その内容を書き換えず、その内容の各行に接頭辞も付けない)、空行 1 行、何の出力が終わったかを伝える `mism: ` で始まる 1 行の文字列 (e.g. `mism: output of paper-26.3-206.jar ended`)を、この順に出力する。
- out-3. mism の標準出力が端末であるとき、out-2 が定める、外部のソフトウェアの出力の始まりと終わりを伝える 2 つの文字列の先頭の `mism` は青色で出力され、その文字列の残りには色が付かない。標準出力が端末でないとき、mism は、色の指定 (エスケープシーケンス)を出力しない。
- out-4. mism 自身は、標準エラー出力に何も出力しない。cli-4 と cli-5 が定める使い方の出力は、この文の対象外である。

## サーバーの新規作成

### バージョンの選択

- sel-1. 利用者が `--version` を省略したとき、mism は、PaperMC がサポート状態 SUPPORTED を付けている Minecraft のバージョンのうち、最も新しくリリースされたものを選ぶ。
- sel-2. 利用者が `--version` に文字列を指定したとき、mism は、PaperMC が Paper (または Folia)を配布している Minecraft のバージョンのうち、その文字列と完全に一致するものを選ぶ。mism は、指定された文字列を別の表記に変換しない (e.g. `26.03` は `26.3` と一致しない)。
- sel-3. mism は、選んだ Minecraft のバージョンに対して PaperMC が配布している Paper (または Folia)のバージョンのうち、番号が最も大きいものを選ぶ。

### 作成の結果

Paper と Folia は、起動したディレクトリに `eula.txt` が無い状態で起動すると、そのディレクトリに `server.properties` と `eula=false` を書いた `eula.txt` を生成して終了し、ワールドを生成しない。
mism は、この動作を使って、利用者がサーバーを本格的に起動する前に、`server.properties` と `eula.txt` を用意する。

- new-1. 利用者が <パス> に相対パスを与えたとき、mism は、その相対パスを、カレントディレクトリを基準にした絶対パスとして扱う。
- new-2. `mism new` が成功したとき、<パス> はディレクトリである。
- new-3. `mism new` が成功したとき、そのディレクトリの直下に、mism が選んだ Paper (または Folia)のバージョンの jar ファイルが、PaperMC が配布している名前 (e.g. `paper-26.3-206.jar`)のまま 1 つある。
- new-4. mism は、jar ファイルを置いた後に、サーバーをそのディレクトリの中で 1 度だけ起動し、サーバーが終了するまで待つ。
- new-5. サーバーが起動している間、mism は、サーバーの標準出力と標準エラー出力の内容を、出力の規則 (out-2)に従って出力する。
- new-6. `mism new` が成功したとき、そのディレクトリの直下の `eula.txt` は、`eula=true` という記述を含み、`eula=false` という記述を含まず、サーバーが書いた他の内容をそのまま含む。
- new-7. mism は、`eula.txt` を書き換える前に、利用者に確認を求めない。利用者は、`mism new` を実行することで Minecraft の EULA に同意したものとする。
- new-8. `mism new` が成功したとき、そのディレクトリの直下に `server.properties` がある。
- new-9. `mism new` が成功したとき、そのディレクトリの直下に `mism.toml` という名前の TOML 形式のファイルがあり、そのファイルは、mism がそのサーバーに Paper と Folia のどちらを使ったか、Minecraft のバージョン、Paper (または Folia)のバージョンの 3 つを記録している。
- new-10. `mism new` が成功したとき、mism は、mism がそのサーバーに使ったのが Paper なら `paper`、Folia なら `folia`、Minecraft のバージョン、Paper (または Folia)のバージョン、作成したディレクトリの絶対パスをこの順に空白 1 文字で区切った記述を、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。

### エラー

- err-1. 利用者が指定した <パス> に、ファイル、ディレクトリ、シンボリックリンク (リンク先の無いものを含む)のいずれかが既に存在するとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-2. 利用者が指定した <パス> の親ディレクトリが存在しないとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-3. 利用者が `--version` に指定した文字列と一致する Minecraft のバージョンを PaperMC が配布していないとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-4. 利用者が `--version` を省略し、PaperMC が配布している Minecraft のバージョンの中に PaperMC がサポート状態 SUPPORTED を付けているものが 1 つも無いとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-5. mism が PaperMC との通信に失敗したとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-6. mism がダウンロードした jar ファイルの SHA-256 が、PaperMC が公開している値と一致しないとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-7. サーバーが終了した後に、`eula.txt` と `server.properties` の両方が作成中のディレクトリに揃っていないとき、mism は、サーバーの初回起動の失敗として、サーバーの作成を中止してエラーを報告する。
- err-8. mism がサーバーの作成を中止してエラーを報告したとき、利用者が指定した <パス> には何も存在しない。
- err-9. mism が実行を中止してエラーを報告するとき、mism は、何が失敗したか、その原因、利用者が取れる対処を、出力の規則に従って標準出力に出力し、終了ステータス 1 で終了する。この仕様書は、エラーの出力の長さを定めない。

### 中断

- int-1. `mism new` の実行中に mism が SIGINT (Ctrl-C)または SIGTERM を受けたとき、mism は、起動中のサーバーがあればそれを止め、利用者が指定した <パス> に何も残さずに終了する。

## バージョンの列挙

- ver-1. 利用者が `mism versions paper` (または `mism versions folia`)を実行したとき、mism は、PaperMC が Paper (または Folia)を配布しているすべての Minecraft のバージョンを、リリースが新しい順に、出力の規則に従って 1 つずつ改行で区切って標準出力に出力し、終了ステータス 0 で終了する。
- ver-2. ver-1 で mism が出力する各バージョンの記述は、Minecraft のバージョン、タブ 1 文字、PaperMC がそのバージョンに付けているサポート状態 (SUPPORTED、DEPRECATED、UNSUPPORTED のいずれか)をこの順につないだものである。
- ver-3. mism が PaperMC との通信に失敗したとき、mism は、Minecraft のバージョンを 1 つも出力せず、バージョンの列挙を中止して err-9 と同じ動作をする。

## ダウンロードした jar ファイルの保存

mism は、ダウンロードした jar ファイルを、次に同じ jar ファイルが必要になったときに再利用するために、利用者のホームディレクトリの下のディレクトリ (以下、キャッシュのディレクトリと呼ぶ)に保存する。

- cache-1. 環境変数 `XDG_CACHE_HOME` が設定されているとき、キャッシュのディレクトリは `$XDG_CACHE_HOME/mism` である。
- cache-2. 環境変数 `XDG_CACHE_HOME` が設定されていないとき、キャッシュのディレクトリは `~/.cache/mism` である。
- cache-3. mism が選んだ Paper (または Folia)のバージョンの jar ファイルがキャッシュのディレクトリに存在し、その SHA-256 が PaperMC が公開している値と一致するとき、mism は、その jar ファイルをダウンロードしない。
- cache-4. mism が選んだ Paper (または Folia)のバージョンの jar ファイルがキャッシュのディレクトリに存在し、その SHA-256 が PaperMC が公開している値と一致しないとき、mism は、その jar ファイルをダウンロードし直し、キャッシュのディレクトリにある jar ファイルを置き換える。
- cache-5. mism は、ダウンロードした jar ファイルの SHA-256 を PaperMC が公開している値と照合し、一致しないときは err-6 の動作をする。
- cache-6. mism は、キャッシュのディレクトリにある jar ファイルを、利用者の操作なしには削除しない。利用者が `mism new` を別の Minecraft のバージョンで実行した後も、前の Minecraft のバージョンの jar ファイルはキャッシュのディレクトリに残る。

## プラグインの管理

mism は、サーバーのディレクトリの `plugins/` に置くプラグインの jar ファイルを、検索 (search)、バージョンの列挙 (versions)、キャッシュのディレクトリへの取得 (fetch)、検証 (inspect)、配置 (place)、取得から配置までを一度に行うインストール (install)、一覧 (list)、削除 (remove)のサブコマンドで扱う。
プラグインの取得元は、Modrinth、jar ファイルの URL、手元の jar ファイルの 3 つである。
mism は、プラグインがサーバーで動くかを保証しない。mism は、Modrinth がプラグインの各バージョンについて公開している申告 (リリースの種別、対応するサーバーソフトウェア、対応する Minecraft のバージョン、必須の依存先、公開日時)と、jar ファイルの中のプラグインの宣言 (プラグインの名前、バージョン、必要とする Minecraft のバージョン、Folia への対応、依存先)を利用者に示し、利用者は、それを見てそのプラグインを使うかを判断する。

### 対象のサーバーと取得元の指定

- plg-1. 利用者が `mism plugin place`、`mism plugin install`、`mism plugin remove`、`--global` 無しの `mism plugin list` を実行したとき、mism は、カレントディレクトリの直下に `mism.toml` があればそのディレクトリを対象のサーバーのディレクトリとし、`mism.toml` が無ければ、処理を中止してエラーを報告する。
- plg-2. 利用者が `mism plugin versions` または `mism plugin inspect` を実行したとき、mism は、カレントディレクトリの直下に `mism.toml` があればそのディレクトリを対象のサーバーのディレクトリとし、`mism.toml` が無ければ、対象のサーバー無しで処理を行う。
- plg-3. <取得元の指定> は、次の 3 つのいずれかである。1 つ目は、`modrinth:` に Modrinth のプラグインの識別子 (Modrinth がそのプラグインのページの URL に使う名前。e.g. `luckperms`)を続け、さらに `:` に続く、そのプラグインのバージョンとファイルを絞る属性 (バージョンの番号など。plg-10)の値を 0 個以上付けたもの (e.g. `modrinth:luckperms`、`modrinth:luckperms:v5.5.71-bukkit`、`modrinth:fastasyncworldedit:2.16.1:paper`)である。2 つ目は、`https://` または `http://` で始まる jar ファイルの URL である。3 つ目は、手元の jar ファイルのパスである。利用者が <取得元の指定> としてそのどれでもない文字列を与えたとき、mism は、処理を中止してエラーを報告する。`mism plugin versions` の引数 (vers-1)は、<取得元の指定> ではない。
- plg-10. `modrinth:` の取得元の指定が指す候補は、はじめ、そのプラグインの Modrinth のすべてのバージョンのすべてのファイルである。mism は、候補を、バージョンの番号、そのバージョンに対応すると Modrinth が申告しているサーバーソフトウェア、そのバージョンに対応すると Modrinth が申告している Minecraft のバージョン、リリースの種別、ファイルの名前の 5 つの属性で、この順に絞る。バージョンの番号の値は、利用者が与えた最初の値であり、利用者が値を与えず候補が 1 種類の番号しか持たなければ、その番号である。それより後の属性について、残っている候補がその属性に 1 種類の値しか持たなければ、mism は、その属性を飛ばす。残っている候補がその属性に 2 種類以上の値を持てば、mism は、利用者が与えた次の値をその属性の値とする。属性の値が決まるたびに、mism は、候補を、その属性にその値を持つものだけにする。属性の値が一覧であるとき (対応するサーバーソフトウェアと対応する Minecraft のバージョン)、残っている候補がその属性に持つ値の種類を、mism は、一覧の要素ごとではなく一覧ごとに数え (候補の一覧が全部同じなら、候補がその属性に持つ値の種類は 1 種類である)、利用者が与える値は一覧の要素であり、mism は、候補を、その属性の一覧にその値を含むものだけにする。利用者が与えた値を持つ候補が 1 つも無いとき、mism は、処理を中止してエラーを報告し、その属性の名前と候補が持つ値を示す。候補が 1 つになったとき、その候補が、その取得元の指定が指すファイルである。候補が 1 つになった後に利用者が与えた値が残っているとき、mism は、処理を中止してエラーを報告する。
- plg-11. 利用者が与えた値が尽き、次の属性について候補が 2 種類以上の値を持つとき、標準入力が端末であり利用者が `--yes` を付けていなければ、mism は、その属性の名前と候補が持つ値 (値が一覧である属性では、候補の一覧の要素。バージョンの番号は、その番号を持つバージョンの公開日時が新しい順に、それ以外の属性は文字列の昇順に)を改行で区切って 1 つずつ標準出力に出力し、値を 1 つ標準入力から改行まで読む。入力が mism が出力した値のどれかであれば、mism は、それをその属性の値とする。入力がそのどれでもないとき (空の入力を含む)、mism は、処理を中止してエラーを報告する。標準入力が端末でないとき、または利用者が `--yes` を付けたとき、mism は、尋ねずに処理を中止してエラーを報告し、その属性の名前と候補が持つ値を示す。
- plg-12. mism が標準出力に出力し `mism.toml` に記録する `modrinth:` の取得元の指定は、`modrinth:` にプラグインの識別子、`:`、バージョンの番号を続け、さらに plg-10 で飛ばさなかった属性の値を、使った順に `:` に続けて付けたものである (e.g. `modrinth:luckperms:v5.5.71-bukkit`、`modrinth:fastasyncworldedit:2.16.1:paper`)。Modrinth のそのプラグインのバージョンとファイルが変わっていなければ、利用者がこの形の取得元の指定を与えたとき、mism は、尋ねずに、候補を、mism がその取得元の指定を出力したときに定めたファイルと同じファイルに定める。

### サブコマンドに共通する規則

- plg-4. mism がプラグインを対象のサーバーの `plugins/` に置いたとき、`mism.toml` は、そのプラグインの記録として、プラグインの名前 (plg-5)、取得元の指定 (plg-3 の形)、jar ファイルの名前、jar ファイルの SHA-256 の 4 つを持つ。
- plg-5. プラグインの名前は、取得元が Modrinth ならそのプラグインの Modrinth での名前であり、URL なら fetch-2 で決めた名前であり、手元の jar ファイルなら jar ファイルの名前から `.jar` を除いたものである。
- plg-6. プラグインの名前が空、`.`、`..` のいずれかのとき、mism は、処理を中止してエラーを報告する。
- plg-7. `mism plugin place`、`mism plugin install`、`mism plugin remove` が対象のサーバーの `plugins/` を変えたとき、mism は、その変更がサーバーの次の起動で反映される旨を標準出力に出力する。mism は、サーバーが動いているかを確かめない。
- plg-8. `mism plugin` のサブコマンドが処理を中止してエラーを報告したとき、対象のサーバーの `plugins/` と `mism.toml` は、そのサブコマンドの実行の前と同じである。
- plg-9. `mism plugin` のサブコマンドの出力の中で、mism は、並べる値をタブ 1 文字で区切り、1 つの値が一覧であるときはその要素を `,` で区切り、値が無いときは `-` を出力する。

### 検索 (search)

- srch-1. 利用者が `mism plugin search <語>` を実行したとき、mism は、Modrinth で <語> を検索し、Modrinth が関連の高い順に返すプラグインのうち最初の <件数> 件まで (利用者が `--limit` を省略したときは 10 件まで)を、出力の規則に従って 1 つずつ改行で区切って標準出力に出力し、終了ステータス 0 で終了する。
- srch-2. srch-1 で mism が出力する各プラグインの記述は、`modrinth:` に続くそのプラグインの識別子 (plg-3)、プラグインの名前、そのプラグインのバージョンのうち、対応すると Modrinth が申告しているサーバーソフトウェアに `paper` または `folia` を含むものの中で公開日時が最も新しいもののバージョンの番号、そのバージョンに対応すると Modrinth が申告しているサーバーソフトウェアの一覧、そのバージョンに対応すると Modrinth が申告している Minecraft のバージョンのうち最も新しいものをこの順に並べたものである (e.g. `modrinth:luckperms	LuckPerms	v5.5.71-bukkit	bukkit,folia,paper,spigot	26.3`)。
- srch-3. 見つかったプラグインが 0 件のとき、mism は、プラグインを 1 つも出力せず、終了ステータス 0 で終了する。
- srch-4. mism が Modrinth との通信に失敗したとき、mism は、検索を中止して err-9 と同じ動作をする。
- srch-5. 利用者が `--limit` に 10 以上 100 以下の整数以外を与えたとき、mism は、処理を中止してエラーを報告する。

### バージョンの列挙 (versions)

- vers-1. 利用者が `mism plugin versions modrinth:<識別子>` を実行したとき、mism は、値の名前の記述 (vers-6)を出力し、その後に、そのプラグインの Modrinth のバージョンを、公開日時が新しい順に、出力の規則に従って 1 つずつ改行で区切って標準出力に出力し、終了ステータス 0 で終了する。
- vers-2. vers-1 で mism が出力する各バージョンの記述は、バージョンの番号、リリースの種別 (`release`、`beta`、`alpha` のいずれか)、そのバージョンに対応すると Modrinth が申告しているサーバーソフトウェアの一覧、そのバージョンに対応すると Modrinth が申告している Minecraft のバージョンのうち最も新しいもの、必須と Modrinth が申告している依存先の識別子 (plg-3 の識別子)の一覧をこの順に並べたものである。
- vers-3. 対象のサーバーがあるとき (plg-2)、mism は、vers-2 の記述の末尾に、そのバージョンを対象のサーバーと照らし合わせた結果を足す。結果は、対応するサーバーソフトウェアの一覧に対象のサーバーのサーバーソフトウェア (Paper なら `paper`、Folia なら `folia`)があり、対応する Minecraft のバージョンの一覧に対象のサーバーの Minecraft のバージョンがあるとき `match`、対応するサーバーソフトウェアの一覧に対象のサーバーのサーバーソフトウェアがあるが、対応する Minecraft のバージョンの一覧に対象のサーバーの Minecraft のバージョンが無いとき `software-only`、対応するサーバーソフトウェアの一覧に対象のサーバーのサーバーソフトウェアが無いとき `mismatch`、対応するサーバーソフトウェアの一覧が分からない (insp-2 の `unknown`)とき `unknown` のいずれかである (e.g. 対象のサーバーが Minecraft のバージョン 26.3 の Paper のとき `v5.5.71-bukkit	release	bukkit,folia,paper,spigot	26.3	-	match`)。
- vers-4. 利用者が `mism plugin versions` の引数として `modrinth:` に続く識別子以外の文字列を与えたとき、mism は、処理を中止してエラーを報告する。
- vers-5. mism が Modrinth との通信に失敗したとき、mism は、値の名前の記述も Modrinth のバージョンの記述も出力せず、バージョンの列挙を中止して err-9 と同じ動作をする。
- vers-6. 値の名前の記述は、vers-2 の各値の名前 `version`、`release_type`、`software`、`newest_minecraft_version`、`required_dependencies` をこの順にタブ 1 文字で区切って並べたものであり、対象のサーバーがあるとき (vers-3)は、その末尾にタブ 1 文字と `declared` が続く。そのプラグインの Modrinth のバージョンが 0 個のときも、mism は、値の名前の記述を出力する。

### キャッシュのディレクトリへの取得 (fetch)

- fetch-1. 利用者が `mism plugin fetch` に `modrinth:` の取得元の指定を与えたとき、mism は、plg-10 と plg-11 のとおり候補を 1 つのファイルに定め、そのファイルをダウンロードし、その内容の SHA-512 を、Modrinth がその jar ファイルの SHA-512 として公開している値と照合する。2 つの値が一致すれば、mism は、その jar ファイルをキャッシュのディレクトリの下に保存する。2 つの値が一致しないとき、mism は、処理を中止してエラーを報告し、キャッシュのディレクトリに何も残さない。
- fetch-2. 利用者が `mism plugin fetch <URL>` を実行したとき、mism は、その URL から jar ファイルをダウンロードし、照合する値が無いので照合せずに、その jar ファイルをキャッシュのディレクトリの下に保存する。mism は、URL のパスの最後の要素 (クエリ文字列を除き、末尾の `.jar` を除いたもの)からプラグインの名前を作り、その名前を標準出力に出力して、プラグインの名前として使う名前を標準入力から利用者に尋ねる。プラグインの名前は、利用者が入力した名前であり、利用者が何も入力しなければ (標準入力が端末でなく入力が無い場合を含む) mism が作った名前である。利用者が `--yes` を付けたとき、mism は、尋ねずに mism が作った名前を使う。この名前の決め方は、`mism plugin fetch`、`mism plugin inspect`、`mism plugin install` のどれで URL から取得するときも同じである。jar ファイルの名前は、プラグインの名前に `.jar` を付けたものである。
- fetch-3. 利用者が `mism plugin fetch <手元の jar ファイルのパス>` を実行したとき、mism は、そのファイルをキャッシュのディレクトリの下に複製する。
- fetch-4. ダウンロードまたは複製した jar ファイルの SHA-256 が、既にキャッシュのディレクトリにある jar ファイルの SHA-256 と同じとき、mism は、ダウンロードまたは複製した jar ファイルが既にあるその jar ファイルと同じである旨 (既にある方のプラグインの名前とパス)を標準出力に出力し、新しい jar ファイルを保存せず、既にある方の jar ファイルとプラグインの名前をそのまま使う。この取得の後、`mism plugin list --global` (list-4)は、その jar ファイルの取得元の指定とバージョンの番号として今回の取得のものを出力し、配置 (place-1)で、mism は、今回の取得元の指定ではその jar ファイルを見つけ、前の取得元の指定が Modrinth または URL のものなら、前の取得元の指定ではその jar ファイルを見つけない (手元の jar ファイルの取得元の指定は、place-1 のとおり、同じ SHA-256 の jar ファイルを見つける)。mism は、この場合もその取得を成功として扱う。
- fetch-5. `mism plugin fetch` が成功したとき、mism は、その `mism plugin fetch` で mism が取得したプラグインの名前、バージョンの番号 (取得元が Modrinth でなければ、mism は `-` を出力する)、取得元の指定 (取得元が Modrinth なら plg-12 の形、URL と手元の jar ファイルなら利用者が与えたもの)、jar ファイルの SHA-256、キャッシュのディレクトリの中のその jar ファイルの絶対パスをこの順に並べた記述を、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。

### 検証 (inspect)

- insp-1. 利用者が `mism plugin inspect <取得元の指定>` を実行したとき、place-1 の条件でその取得元の指定の jar ファイルがキャッシュのディレクトリに無ければ、mism は、取得 (fetch-1 から fetch-4)を先に行う。mism は、キャッシュのディレクトリにあるその jar ファイルの中のプラグインの宣言 (以下、jar ファイルの宣言)を読み、insp-2 と insp-3 の記述を出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- insp-2. mism は、値の名前、タブ 1 文字、値を並べた記述を、1 つの値につき 1 つ、改行で区切って出力する。mism が出力する値は、次の 13 個である。
  - `name` の値は、プラグインの名前 (plg-5)である。
  - `version` の値は、Modrinth のバージョンの番号である。取得元が Modrinth でなければ、mism は `-` を出力する。
  - `source` の値は、取得元の指定 (取得元が Modrinth なら plg-12 の形、URL と手元の jar ファイルなら利用者が与えたもの)である。
  - `file.name` の値は、jar ファイルの名前である。
  - `file.sha256` の値は、jar ファイルの SHA-256 である。
  - `declaration.name` の値は、jar ファイルの宣言にあるプラグインの名前である。
  - `declaration.version` の値は、jar ファイルの宣言にあるプラグインのバージョンである。
  - `compatibility.minimum_minecraft_version` の値は、jar ファイルの宣言が示す、そのプラグインが必要とする最小の Minecraft のバージョンである。
  - `compatibility.minecraft_versions` の値は、そのプラグインのそのバージョンに対応すると Modrinth が申告している Minecraft のバージョンの一覧である。
  - `compatibility.software` の値は、そのプラグインが対応するサーバーソフトウェアの一覧であり、jar ファイルの宣言から分かるものと、そのバージョンに対応すると Modrinth が申告しているサーバーソフトウェアを合わせたものである。jar ファイルの宣言が Folia への対応を示していれば、この一覧は `folia` を含む。jar ファイルの宣言が Paper 専用のプラグインの形式であれば、この一覧は `paper` を含む。
  - `compatibility.folia_supported` の値は、jar ファイルの宣言が Folia への対応を示しているかである。
  - `compatibility.required_dependencies` の値は、必須の依存先の一覧であり、jar ファイルの宣言が必須としている依存先の名前と、必須と Modrinth が申告している依存先の識別子 (plg-3 の識別子)を合わせたものである。
  - `compatibility.optional_dependencies` の値は、任意の依存先の一覧であり、jar ファイルの宣言が任意としている依存先の名前である。

  `compatibility` で始まる値の記述は、値の後にタブ 1 文字とその値の出どころを持つ。出どころは、その値が jar ファイルの宣言から分かったなら `jar`、Modrinth の申告から分かったなら `modrinth`、両方から分かったなら `jar,modrinth`、どちらからも分からなければ `-` である。どちらからも分からない値を、mism は `unknown` と出力する。一覧の値の出どころは、その要素の出どころを合わせたものである。
- insp-3. 対象のサーバーがあるとき (plg-2)、mism は、insp-2 の記述の後に、判定の名前、タブ 1 文字、値を並べた記述を、該当する判定につき 1 つ、改行で区切って出力する。判定は、次の 4 つである。
  - mism は、`declared` を常に出力する。その値は、insp-2 の対応するサーバーソフトウェアの一覧と対応する Minecraft のバージョンの一覧についての vers-3 の結果 (vers-3 の 4 つの語のいずれか)である。
  - mism は、jar ファイルの宣言が示す最小の Minecraft のバージョンが対象のサーバーの Minecraft のバージョンより新しいとき、または対象のサーバーが Folia で jar ファイルの宣言が Folia への対応を示していないとき、`incompatible` をその理由とともに出力する。
  - mism は、insp-2 の必須の依存先のうち対象のサーバーに無いものがあるとき、`missing` をその依存先の識別子とともに出力する。依存先が名前 (jar ファイルの宣言から分かったもの)のとき、対象のサーバーの `plugins/` の jar ファイルのどれかがその名前を宣言していれば、その依存先は対象のサーバーにある。依存先が Modrinth の識別子 (Modrinth の申告から分かったもの)のとき、対象のサーバーの `mism.toml` に、取得元の指定の識別子がそれと同じプラグインの記録があれば、その依存先は対象のサーバーにある。
  - mism は、対象のサーバーの `plugins/` に、jar ファイルの宣言にあるプラグインの名前と同じ名前を宣言する別の jar ファイルがあるとき、`conflict` をそのファイルの名前とともに出力する。
- insp-4. 検証する jar ファイルがプラグインの宣言を持たないとき、mism は、検証を中止してエラーを報告する。

### 配置 (place)

- place-1. 利用者が `mism plugin place <取得元の指定>` を実行したとき、キャッシュのディレクトリに、利用者が与えた文字列と同じ取得元の指定 (plg-12 の形)で取得 (fetch)した jar ファイル (fetch-4 で取得元の指定を置き換えた jar ファイルを、mism は、置き換えた後の取得元の指定で取得したものと見なす。手元の jar ファイルの指定では、mism は、指定された jar ファイルと同じ SHA-256 の jar ファイルをその取得元の指定で取得したものと見なす)が無いとき、mism は、処理を中止してエラーを報告する。mism は、配置 (place)では jar ファイルをダウンロードせず、Modrinth に問い合わせない。
- place-2. 配置が成功したとき、対象のサーバーの `plugins/` の直下にその jar ファイルがあり (`plugins/` が無ければ mism がそれを作る)、`mism.toml` にそのプラグインの記録 (plg-4)がある。
- place-3. `mism.toml` に、配置しようとしているプラグインと同じ名前のプラグインの記録が既にあるとき、mism は、処理を中止してエラーを報告し、`plugins/` と `mism.toml` を変えない。
- place-4. `plugins/` の直下に、配置しようとしている jar ファイルと同じ名前の jar ファイルが既にあるとき、mism は、処理を中止してエラーを報告し、`plugins/` と `mism.toml` を変えない。
- place-5. 配置が成功したとき、mism は、配置したプラグインの名前、バージョンの番号 (取得元が Modrinth でなければ、mism は `-` を出力する)、jar ファイルの名前をこの順に並べた記述を、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- place-6. 配置が成功したとき、mism が標準出力に出力したものの中で、place-5 の記述の前に、キャッシュのディレクトリにあるその jar ファイルについての検証の記述 (insp-2、insp-3)がある。insp-3 の判定に `incompatible` または `conflict` が 1 つでもあるとき、mism は、検証の記述を出力した後に処理を中止してエラーを報告し、`plugins/` と `mism.toml` を変えない。その jar ファイルがプラグインの宣言を持たないとき、mism は、insp-4 のとおり処理を中止してエラーを報告し、`plugins/` と `mism.toml` を変えない。

### インストール (install)

- inst-1. 利用者が `mism plugin install <取得元の指定>` を `--lazy` 無しで実行したとき、mism は、取得元が Modrinth なら plg-10 と plg-11 のとおり候補を 1 つのファイルに定め、URL と手元の jar ファイルならそのファイルをインストールする jar ファイルとする。
- inst-2. 利用者が `modrinth:` の取得元の指定にバージョンの番号の値を付けず、`--lazy` を付けて `mism plugin install` を実行したとき、mism は、バージョンの番号を尋ねる代わりに、候補のバージョンのうち vers-3 の結果が `match` であるものの中で公開日時が最も新しいもの 1 つを選び、候補をそのバージョンのファイルだけにする。それより後の属性について、mism は、plg-10 と plg-11 のとおり候補を 1 つのファイルに定める。`match` のバージョンが 1 つも無いとき、mism は、処理を中止してエラーを報告し、他のバージョンを選ばない。
- inst-3. 利用者が `--lazy` を、URL または手元の jar ファイルの指定と一緒に付けたとき、またはバージョンの番号の値を付けた `modrinth:` の取得元の指定と一緒に付けたとき、mism は、`--lazy` を無視する。
- inst-4. `mism plugin install` の標準出力は、取得 (fetch-1 から fetch-4)、検証 (insp-2、insp-3)、確認 (inst-5)、配置 (place-5)の順である。インストールが成功したとき、`plugins/` と `mism.toml` は place-2 の状態であり、place-3 と place-4 の条件は、インストールにも当てはまる。insp-3 の判定に `incompatible` または `conflict` が 1 つでもあるとき、mism は、検証の記述を出力した後に処理を中止してエラーを報告し、`plugins/` と `mism.toml` を変えない。取得した jar ファイルがプラグインの宣言を持たないとき、mism は、insp-4 のとおり処理を中止してエラーを報告し、`plugins/` と `mism.toml` を変えない。
- inst-5. 利用者が `--yes` を付けていないとき、mism は、検証の記述の後に、その jar ファイルを `plugins/` に置くかを標準出力で尋ね、標準入力から改行までの入力を読む。その入力が `y` または `yes` のとき、mism は、配置に進む。それ以外のとき、mism は、その jar ファイルを置かない旨を標準出力に出力し、`plugins/` と `mism.toml` を変えずに終了ステータス 0 で終了する。
- inst-6. 利用者が `--yes` を付けたとき、mism は、尋ねずに配置に進む。
- inst-7. 利用者が `--yes` を付けず、標準入力が端末でないとき、mism は、尋ねずに処理を中止してエラーを報告し、`--yes` を付けるよう利用者に案内する。

### 一覧 (list)

- list-1. 利用者が `mism plugin list` を実行したとき、mism は、対象のサーバーの `mism.toml` の記録と `plugins/` の直下の jar ファイルを突き合わせ、その結果を 1 つずつ改行で区切って、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- list-2. list-1 で mism が出力する各記述は、状態、プラグインの名前、バージョンの番号、jar ファイルの名前、取得元の指定 (plg-3 の形。`mism.toml` にそのプラグインの記録が無ければ、mism は `-` を出力する)をこの順に並べたものである。状態は、`mism.toml` に記録があり `plugins/` の jar ファイルの SHA-256 が記録の SHA-256 と一致するとき `ok`、記録があり `plugins/` に jar ファイルが無いとき `missing`、記録があり `plugins/` の jar ファイルの SHA-256 が `mism.toml` の記録の SHA-256 と違うとき `changed`、記録が無く `plugins/` に jar ファイルがあるとき `unmanaged` のいずれかである (e.g. `ok	LuckPerms	v5.5.71-bukkit	LuckPerms-Bukkit-5.5.71.jar	modrinth:luckperms:v5.5.71-bukkit`)。`unmanaged` の jar ファイルについて、mism は、プラグインの名前として jar ファイルの名前から `.jar` を除いたものを出力し、バージョンの番号と取得元の指定として `-` を出力する。
- list-3. 利用者が `mism plugin list --global` を実行したとき、mism は、キャッシュのディレクトリにあるプラグインを、1 つずつ改行で区切って、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- list-4. list-3 で mism が出力する各記述は、プラグインの名前、バージョンの番号 (取得元が Modrinth でなければ、mism は `-` を出力する)、jar ファイルの SHA-256、取得元の指定 (plg-3 の形)をこの順に並べたものである。fetch-4 で取得元の指定を置き換えた jar ファイルについて、mism は、置き換えた後の取得元の指定とバージョンの番号を出力する。

### 削除 (remove)

- rm-1. 利用者が `mism plugin remove <プラグインの名前>` を実行したとき、mism は、対象のサーバーの `plugins/` から `mism.toml` の記録にある jar ファイルを削除し、`mism.toml` からそのプラグインの記録を削除し、終了ステータス 0 で終了する。mism は、プラグインが `plugins/` の下に作ったディレクトリやファイルは削除しない。
- rm-2. 利用者が与えた <プラグインの名前> の記録が `mism.toml` に無いとき、mism は、処理を中止してエラーを報告し、`plugins/` と `mism.toml` を変えない。
- rm-3. `mism.toml` の記録にある jar ファイルが `plugins/` に無いとき、mism は、その旨を標準出力に出力し、記録だけを削除して終了ステータス 0 で終了する。

## データパックの管理

データパックは、関数、進捗、ワールドの生成の設定などのデータを Minecraft のサーバーに読み込ませるための zip 形式のファイルである。
mism は、対象のサーバーのワールドのディレクトリの `datapacks/` に置くデータパックのファイルを、プラグインと同じく、検索 (search)、バージョンの列挙 (versions)、キャッシュのディレクトリへの取得 (fetch)、検証 (inspect)、配置 (place)、取得から配置までを一度に行うインストール (install)、一覧 (list)、削除 (remove)のサブコマンドで扱う。
データパックの取得元は、Modrinth、データパックのファイルの URL、手元のデータパックのファイルの 3 つである。
Modrinth は、プラグインとデータパックの各バージョンに、そのバージョンに対応するソフトウェアの一覧を付けて公開しており、Modrinth がデータパックのバージョンに付ける一覧は `datapack` を含む。
データパックのファイルは、zip の最上位に `pack.mcmeta` という名前のファイルを持ち、そのデータパックが対応するデータパックの形式の番号の範囲を `pack.mcmeta` の中で宣言する。Minecraft の各バージョンは、データパックの形式の番号を 1 つ持ち、データパックの形式の番号は、メジャー番号とマイナー番号の 2 つの整数からなる (e.g. Minecraft 26.3 のデータパックの形式の番号は `121.0` であり、そのメジャー番号は `121`、マイナー番号は `0` である)。
mism は、データパックがサーバーで動くかを保証しない。mism は、Modrinth がデータパックの各バージョンについて公開している申告 (リリースの種別、対応する Minecraft のバージョン、必須の依存先、公開日時)と、`pack.mcmeta` の宣言 (対応するデータパックの形式の番号の範囲)を利用者に示し、利用者は、それを見てそのデータパックを使うかを判断する。

### 対象のサーバーと取得元の指定

- dp-1. 利用者が `mism datapack place`、`mism datapack install`、`mism datapack remove`、`--global` 無しの `mism datapack list` を実行したとき、mism は、カレントディレクトリの直下に `mism.toml` があればそのディレクトリを対象のサーバーのディレクトリとし、`mism.toml` が無ければ、処理を中止してエラーを報告する。
- dp-2. 利用者が `mism datapack versions` または `mism datapack inspect` を実行したとき、mism は、カレントディレクトリの直下に `mism.toml` があればそのディレクトリを対象のサーバーのディレクトリとし、`mism.toml` が無ければ、対象のサーバー無しで処理を行う。
- dp-3. 対象のサーバーのワールドのディレクトリは、対象のサーバーのディレクトリの直下の `server.properties` が持つ `level-name` の値を、mism が、対象のサーバーのディレクトリを基準にしたパスとして解釈したディレクトリである (e.g. `level-name=world` なら、ワールドのディレクトリは `<対象のサーバーのディレクトリ>/world` であり、`level-name` の値が絶対パスなら、ワールドのディレクトリはその絶対パスである)。dp-1 のサブコマンド (`--global` 無しの `mism datapack list` を含む)を利用者が実行したとき、`server.properties` が無いか、`server.properties` が `level-name` を持たないか、`level-name` の値が空であれば、mism は、処理を中止してエラーを報告する。
- dp-4. データパックの <取得元の指定> は、次の 3 つのいずれかである。1 つ目は、`modrinth:` に Modrinth のデータパックの識別子 (識別子は、Modrinth がそのデータパックのページの URL に使う名前である。e.g. `true-ending`)を続け、さらに `:` に続く、そのデータパックのバージョンとファイルを絞る属性 (dp-5)の値を 0 個以上付けたもの (e.g. `modrinth:true-ending`、`modrinth:true-ending:1.1.4b`)である。2 つ目は、`https://` または `http://` で始まるデータパックのファイルの URL である。3 つ目は、手元のデータパックのファイルのパスである。利用者が `mism datapack` のサブコマンドに <取得元の指定> としてそのどれでもない文字列を与えたとき、mism は、処理を中止してエラーを報告する。`mism datapack versions` の引数 (dvers-1)は、<取得元の指定> ではない。
- dp-5. `modrinth:` のデータパックの取得元の指定が指す候補は、はじめ、そのデータパックの Modrinth のバージョンのうち、そのバージョンに対応すると Modrinth が申告しているソフトウェアの一覧に `datapack` を含むものの、すべてのファイルから、Modrinth がファイルの種類 (e.g. 必須のリソースパック、任意のリソースパック)を示しているファイルを除いたものである。mism は、候補を、バージョンの番号、そのバージョンに対応すると Modrinth が申告している Minecraft のバージョン、リリースの種別、ファイルの名前の 4 つの属性で、この順に、plg-10 と同じ規則で絞る。利用者が与えた値が尽き、次の属性について候補が 2 種類以上の値を持つとき、mism は、plg-11 と同じ規則で、利用者に値を尋ねるか、尋ねずに処理を中止してエラーを報告する。
- dp-6. mism が標準出力に出力し `mism.toml` に記録する `modrinth:` のデータパックの取得元の指定は、`modrinth:` にデータパックの識別子、`:`、バージョンの番号を続け、さらに dp-5 で (plg-10 と同じ規則で) mism が飛ばさなかった属性の値を、使った順に `:` に続けて付けたものである (e.g. `modrinth:true-ending:1.1.4b:1.21.9`)。Modrinth のそのデータパックのバージョンとファイルが変わっていなければ、利用者がこの形の取得元の指定を与えたとき、mism は、利用者に値を尋ねずに、候補を、mism がその取得元の指定を出力したときに定めたファイルと同じファイルに定める。

### サブコマンドに共通する規則

- dp-7. mism がデータパックのファイルを対象のサーバーのワールドのディレクトリの `datapacks/` に置いたとき、`mism.toml` は、そのデータパックの記録として、データパックの名前 (dp-8)、取得元の指定 (dp-4 の形)、データパックのファイルの名前、そのファイルの SHA-256 の 4 つを持つ。
- dp-8. データパックの名前は、取得元が Modrinth ならそのデータパックの Modrinth での名前であり、URL なら dfetch-2 で決めた名前であり、手元のデータパックのファイルならそのファイルの名前から `.zip` を除いたものである。
- dp-9. データパックの名前が空、`.`、`..` のいずれかのとき、mism は、処理を中止してエラーを報告する。
- dp-10. `mism datapack place`、`mism datapack install`、`mism datapack remove` が対象のサーバーのワールドのディレクトリの `datapacks/` を変えたとき、mism は、その変更がサーバーの次の起動で反映される旨を標準出力に出力する。mism は、サーバーが動いているかを確かめない。
- dp-11. `mism datapack` のサブコマンドが処理を中止してエラーを報告したとき、対象のサーバーのワールドのディレクトリと `mism.toml` は、そのサブコマンドの実行の前と同じである。実行の前にワールドのディレクトリのパスに何も無かったとき、そのパスには、実行の後も何も無い。
- dp-12. `mism datapack` のサブコマンドの出力の中で、mism は、並べる値をタブ 1 文字で区切り、1 つの値が一覧であるときはその要素を `,` で区切り、値が無いときは `-` を出力する。

### 検索 (search)

- dsrch-1. 利用者が `mism datapack search <語>` を実行したとき、mism は、Modrinth で <語> をデータパックに限って検索し、Modrinth が <語> との関連の高い順に返すデータパックのうち最初の <件数> 件まで (利用者が `--limit` を省略したときは 10 件まで)を、出力の規則に従って 1 つずつ改行で区切って標準出力に出力し、終了ステータス 0 で終了する。
- dsrch-2. dsrch-1 で mism が出力する各データパックの記述は、`modrinth:` に続くそのデータパックの識別子 (dp-4)、データパックの名前、そのデータパックのバージョンのうち、そのバージョンに対応すると Modrinth が申告しているソフトウェアの一覧に `datapack` を含むものの中で公開日時が最も新しいもののバージョンの番号、そのバージョンに対応すると Modrinth が申告している Minecraft のバージョンのうち最も新しいものをこの順に並べたものである (e.g. `modrinth:true-ending	True Ending - Ender Dragon Overhaul	1.1.4d	26.1.2`)。
- dsrch-3. 見つかったデータパックが 0 件のとき、mism は、データパックを 1 つも出力せず、終了ステータス 0 で終了する。
- dsrch-4. mism が Modrinth との通信に失敗したとき、mism は、データパックを 1 つも出力せず、検索を中止して err-9 と同じ動作をする。
- dsrch-5. 利用者が `mism datapack search` の `--limit` に 10 以上 100 以下の整数以外を与えたとき、mism は、処理を中止してエラーを報告する。

### バージョンの列挙 (versions)

- dvers-1. 利用者が `mism datapack versions modrinth:<識別子>` を実行したとき、mism は、値の名前の記述 (dvers-6)を出力し、その後に、そのデータパックの Modrinth のバージョンのうち、そのバージョンに対応すると Modrinth が申告しているソフトウェアの一覧に `datapack` を含むものを、公開日時が新しい順に、出力の規則に従って 1 つずつ改行で区切って標準出力に出力し、終了ステータス 0 で終了する。
- dvers-2. dvers-1 で mism が出力する各バージョンの記述は、バージョンの番号、リリースの種別 (`release`、`beta`、`alpha` のいずれか)、そのバージョンに対応すると Modrinth が申告している Minecraft のバージョンのうち最も新しいもの、必須と Modrinth が申告している依存先の識別子 (Modrinth がその依存先のページの URL に使う名前)の一覧をこの順に並べたものである。
- dvers-3. 対象のサーバーがあるとき (dp-2)、mism は、dvers-2 の記述の末尾に、そのバージョンを対象のサーバーと照らし合わせた結果を足す。結果は、そのバージョンに対応すると Modrinth が申告している Minecraft のバージョンの一覧に対象のサーバーの Minecraft のバージョンがあるとき `match`、無いとき `mismatch` である (e.g. 対象のサーバーが Minecraft のバージョン 26.1.2 のサーバーのとき `1.1.4d	release	26.1.2	-	match`)。
- dvers-4. 利用者が `mism datapack versions` の引数として `modrinth:` に続く識別子以外の文字列を与えたとき、mism は、処理を中止してエラーを報告する。
- dvers-5. mism が Modrinth との通信に失敗したとき、mism は、値の名前の記述も Modrinth のバージョンの記述も出力せず、バージョンの列挙を中止して err-9 と同じ動作をする。
- dvers-6. 値の名前の記述は、dvers-2 の各値の名前 `version`、`release_type`、`newest_minecraft_version`、`required_dependencies` をこの順にタブ 1 文字で区切って並べたものであり、対象のサーバーがあるとき (dvers-3)は、その末尾にタブ 1 文字と `declared` が続く。dvers-1 が出力する Modrinth のバージョンが 0 個のときも、mism は、値の名前の記述を出力する。

### キャッシュのディレクトリへの取得 (fetch)

- dfetch-1. 利用者が `mism datapack fetch` に `modrinth:` の取得元の指定を与えたとき、mism は、dp-5 のとおり候補を 1 つのファイルに定め、そのファイルをダウンロードし、その内容の SHA-512 を、Modrinth がそのファイルの SHA-512 として公開している値と照合する。2 つの値が一致すれば、mism は、そのデータパックのファイルをキャッシュのディレクトリの下に保存する。2 つの値が一致しないとき、mism は、処理を中止してエラーを報告し、キャッシュのディレクトリに何も残さない。
- dfetch-2. 利用者が `mism datapack fetch <URL>` を実行したとき、mism は、その URL からデータパックのファイルをダウンロードし、照合する値が無いので照合せずに、そのファイルをキャッシュのディレクトリの下に保存する。mism は、URL のパスの最後の要素 (クエリ文字列を除き、末尾の `.zip` を除いたもの)からデータパックの名前を作り、その名前を標準出力に出力して、データパックの名前として使う名前を標準出力で利用者に尋ね、標準入力から読む。データパックの名前は、利用者が入力した名前であり、利用者が何も入力しなければ (標準入力が端末でなく入力が無い場合を含む) mism が作った名前である。利用者が `--yes` を付けたとき、mism は、利用者に名前を尋ねずに mism が作った名前を使う。この名前の決め方は、`mism datapack fetch`、`mism datapack inspect`、`mism datapack install` のどれで URL から取得するときも同じである。データパックのファイルの名前は、データパックの名前に `.zip` を付けたものである。
- dfetch-3. 利用者が `mism datapack fetch <手元のデータパックのファイルのパス>` を実行したとき、mism は、そのファイルをキャッシュのディレクトリの下に複製する。
- dfetch-4. ダウンロードまたは複製したデータパックのファイルの SHA-256 が、既にキャッシュのディレクトリにあるデータパックのファイルの SHA-256 と同じとき、mism は、ダウンロードまたは複製したファイルが既にあるそのファイルと同じである旨 (既にある方のデータパックの名前とパス)を標準出力に出力し、新しいファイルを保存せず、既にある方のファイルとデータパックの名前をそのまま使う。この取得の後、`mism datapack list --global` (dlist-4)は、そのファイルの取得元の指定とバージョンの番号として今回の取得のものを出力し、配置 (dplace-1)で、mism は、今回の取得元の指定ではそのファイルを見つけ、前の取得元の指定が Modrinth または URL のものなら、前の取得元の指定ではそのファイルを見つけない (手元のデータパックのファイルの取得元の指定は、dplace-1 のとおり、同じ SHA-256 のファイルを見つける)。mism は、この場合もその取得を成功として扱う。
- dfetch-5. `mism datapack fetch` が成功したとき、mism は、その `mism datapack fetch` で mism が取得したデータパックの名前、バージョンの番号 (取得元が Modrinth でなければ、mism は `-` を出力する)、取得元の指定 (取得元が Modrinth なら dp-6 の形、URL と手元のデータパックのファイルなら利用者が与えたもの)、データパックのファイルの SHA-256、キャッシュのディレクトリの中のそのファイルの絶対パスをこの順に並べた記述を、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。

### 検証 (inspect)

- dinsp-1. 利用者が `mism datapack inspect <取得元の指定>` を実行したとき、dplace-1 の条件でその取得元の指定のデータパックのファイルがキャッシュのディレクトリに無ければ、mism は、取得 (dfetch-1 から dfetch-4)を先に行う。mism は、キャッシュのディレクトリにあるそのファイルの `pack.mcmeta` の内容 (以下、データパックの宣言)を読み、dinsp-2 と dinsp-3 の記述を出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- dinsp-2. mism は、値の名前、タブ 1 文字、値を並べた記述を、1 つの値につき 1 つ、改行で区切って出力する。mism が出力する値は、次の 9 個である。
  - `name` の値は、データパックの名前 (dp-8)である。
  - `version` の値は、Modrinth のバージョンの番号である。取得元が Modrinth でなければ、mism は `-` を出力する。
  - `source` の値は、取得元の指定 (取得元が Modrinth なら dp-6 の形、URL と手元のデータパックのファイルなら利用者が与えたもの)である。
  - `file.name` の値は、データパックのファイルの名前である。
  - `file.sha256` の値は、データパックのファイルの SHA-256 である。
  - `declaration.min_format` の値は、データパックの宣言が示す、対応するデータパックの形式の番号の下限である。
  - `declaration.max_format` の値は、データパックの宣言が示す、対応するデータパックの形式の番号の上限である。
  - `modrinth.minecraft_versions` の値は、そのデータパックのそのバージョンに対応すると Modrinth が申告している Minecraft のバージョンの一覧である。
  - `modrinth.required_dependencies` の値は、そのデータパックのそのバージョンについて必須と Modrinth が申告している依存先の識別子 (Modrinth がその依存先のページの URL に使う名前)の一覧である。

  データパックの宣言が `min_format` と `max_format` を持つとき、下限と上限はその 2 つの値である。データパックの宣言がその 2 つを持たず `supported_formats` を持つとき、下限と上限は `supported_formats` が示す範囲の両端である。データパックの宣言がそのどれも持たず `pack_format` を持つとき、下限と上限は `pack_format` の値である。mism は、宣言の中で整数である番号を整数のまま、2 つの整数の配列である番号を `<1 つ目の整数>.<2 つ目の整数>` の形で出力する。整数の下限は、その整数をメジャー番号とし、マイナー番号を 0 とする形式の番号を表し、整数の上限は、その整数をメジャー番号とするすべてのマイナー番号の形式の番号を表す。データパックの宣言がそのどれも持たないとき、mism は、下限と上限を `unknown` と出力する。取得元が Modrinth でないとき、mism は、`modrinth` で始まる 2 つの値を `unknown` と出力する。
- dinsp-3. 対象のサーバーがあるとき (dp-2)、mism は、dinsp-2 の記述の後に、判定の名前、タブ 1 文字、値を並べた記述を、次の 3 つの判定のうち出力する条件が成り立つものについて 1 つずつ、改行で区切って出力する。
  - mism は、`declared` を常に出力する。その値は、`modrinth.minecraft_versions` の一覧に対象のサーバーの Minecraft のバージョンがあるとき `match`、無いとき `mismatch`、その一覧が `unknown` のとき `unknown` である。
  - mism は、`pack_format` を常に出力する。その値は、対象のサーバーの Minecraft のバージョンのデータパックの形式の番号が、dinsp-2 の下限と上限の間 (両端を含む)にあるとき `match`、無いとき `mismatch`、下限と上限が `unknown` のとき `unknown` である。
  - mism は、`modrinth.required_dependencies` の依存先のうち、`mism.toml` のプラグインの記録とデータパックの記録のどれの取得元の指定の識別子とも一致しないものがあるとき、`missing` をその依存先の識別子とともに出力する。
- dinsp-4. 検証するデータパックのファイルが zip 形式でないとき、そのファイルが zip の最上位に `pack.mcmeta` を持たないとき、またはデータパックの宣言が `min_format` と `max_format` の片方だけを持つとき、mism は、検証を中止してエラーを報告する。
- dinsp-5. 対象のサーバーがあり (dp-2)、mism が、対象のサーバーの Minecraft のバージョンのデータパックの形式の番号を、対象のサーバーのディレクトリの中のサーバーの jar ファイル (Paper と Folia が初回起動で `versions/` の下に作るもの)から読めないとき、mism は、検証を中止してエラーを報告する。

### 配置 (place)

- dplace-1. 利用者が `mism datapack place <取得元の指定>` を実行したとき、キャッシュのディレクトリに、利用者が与えた文字列と同じ取得元の指定 (dp-6 の形)で取得 (fetch)したデータパックのファイル (dfetch-4 で取得元の指定を置き換えたファイルを、mism は、置き換えた後の取得元の指定で取得したものと見なす。手元のデータパックのファイルの取得元の指定では、mism は、指定されたファイルと同じ SHA-256 のデータパックのファイルをその取得元の指定で取得したものと見なす)が無いとき、mism は、処理を中止してエラーを報告する。mism は、配置 (place)ではデータパックのファイルをダウンロードせず、Modrinth に問い合わせない。
- dplace-2. 配置が成功したとき、対象のサーバーのワールドのディレクトリの `datapacks/` の直下にそのデータパックのファイルがあり (ワールドのディレクトリと `datapacks/` が無ければ、mism がそれらを作る)、`mism.toml` にそのデータパックの記録 (dp-7)がある。
- dplace-3. `mism.toml` に、配置しようとしているデータパックと同じ名前のデータパックの記録が既にあるとき、mism は、処理を中止してエラーを報告し、ワールドのディレクトリと `mism.toml` を変えない。
- dplace-4. `datapacks/` の直下に、配置しようとしているデータパックのファイルと同じ名前のファイル、ディレクトリ、シンボリックリンクのいずれかが既にあるとき、mism は、処理を中止してエラーを報告し、ワールドのディレクトリと `mism.toml` を変えない。
- dplace-5. 配置が成功したとき、mism は、配置したデータパックの名前、バージョンの番号 (取得元が Modrinth でなければ、mism は `-` を出力する)、データパックのファイルの名前をこの順に並べた記述を、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- dplace-6. 配置が成功したとき、mism が標準出力に出力したものの中で、dplace-5 の記述の前に、キャッシュのディレクトリにあるそのデータパックのファイルについての検証の記述 (dinsp-2、dinsp-3)がある。dinsp-4 または dinsp-5 の条件が成り立つとき、mism は、処理を中止してエラーを報告し、ワールドのディレクトリと `mism.toml` を変えない。

### インストール (install)

- dinst-1. 利用者が `mism datapack install <取得元の指定>` を `--lazy` 無しで実行したとき、mism は、取得元が Modrinth なら dp-5 のとおり候補を 1 つのファイルに定め、URL と手元のデータパックのファイルならそのファイルをインストールするファイルとする。
- dinst-2. 利用者が `modrinth:` の取得元の指定にバージョンの番号の値を付けず、`--lazy` を付けて `mism datapack install` を実行したとき、mism は、利用者にバージョンの番号を尋ねる代わりに、候補が属する Modrinth のバージョンのうち dvers-3 の結果が `match` であるものの中で公開日時が最も新しいもの 1 つを選び、候補をその Modrinth のバージョンのファイルだけにする。それより後の属性について、mism は、dp-5 のとおり候補を 1 つのファイルに定める。dvers-3 の結果が `match` である Modrinth のバージョンが 1 つも無いとき、mism は、処理を中止してエラーを報告し、他のバージョンを選ばない。
- dinst-3. 利用者が `--lazy` を、URL または手元のデータパックのファイルの取得元の指定と一緒に付けたとき、またはバージョンの番号の値を付けた `modrinth:` の取得元の指定と一緒に付けたとき、mism は、`--lazy` を無視する。
- dinst-4. `mism datapack install` の標準出力は、取得の記述 (dfetch-1 から dfetch-4)、検証の記述 (dinsp-2、dinsp-3)、置くかの問い (dinst-5)、配置の記述 (dplace-5)、変更が反映される旨 (dp-10)の順である。インストールが成功したとき、ワールドのディレクトリと `mism.toml` は dplace-2 の状態であり、dplace-3 と dplace-4 の条件は、インストールにも当てはまる。dinsp-4 または dinsp-5 の条件が成り立つとき、mism は、処理を中止してエラーを報告し、ワールドのディレクトリと `mism.toml` を変えない。
- dinst-5. 利用者が `--yes` を付けていないとき、mism は、検証の記述の後に、mism がそのデータパックのファイルを `datapacks/` に置くかを標準出力で利用者に尋ね、標準入力から改行までの入力を読む。その入力が `y` または `yes` のとき、mism は、そのファイルを `datapacks/` に置く。それ以外のとき、mism は、そのファイルを置かない旨を標準出力に出力し、ワールドのディレクトリと `mism.toml` を変えずに終了ステータス 0 で終了する。
- dinst-6. 利用者が `--yes` を付けたとき、mism は、利用者に尋ねずにそのデータパックのファイルを `datapacks/` に置く。
- dinst-7. 利用者が `--yes` を付けず、標準入力が端末でないとき、mism は、利用者に尋ねずに処理を中止してエラーを報告し、`--yes` を付けるよう利用者に案内する。

### 一覧 (list)

- dlist-1. 利用者が `mism datapack list` を実行したとき、mism は、対象のサーバーの `mism.toml` のデータパックの記録と、ワールドのディレクトリの `datapacks/` の直下のデータパックのファイルを突き合わせ、その結果を 1 つずつ改行で区切って、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- dlist-2. dlist-1 で mism が出力する各記述は、状態、データパックの名前、バージョンの番号、データパックのファイルの名前、取得元の指定 (dp-4 の形。`mism.toml` にそのデータパックの記録が無ければ、mism は `-` を出力する)をこの順に並べたものである。状態は、`mism.toml` に記録があり `datapacks/` のファイルの SHA-256 が記録の SHA-256 と一致するとき `ok`、記録があり `datapacks/` にファイルが無いとき `missing`、記録があり `datapacks/` のファイルの SHA-256 が記録の SHA-256 と違うとき `changed`、記録が無く `datapacks/` に名前が `.zip` で終わるファイルがあるとき `unmanaged` のいずれかである (e.g. `ok	True Ending - Ender Dragon Overhaul	1.1.4d	tru.e-ending-1.1.4d.zip	modrinth:true-ending:1.1.4d`)。`unmanaged` のファイルについて、mism は、データパックの名前としてファイルの名前から `.zip` を除いたものを出力し、バージョンの番号と取得元の指定として `-` を出力する。
- dlist-3. 利用者が `mism datapack list --global` を実行したとき、mism は、キャッシュのディレクトリにあるデータパックのファイルを、1 つずつ改行で区切って、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。
- dlist-4. dlist-3 で mism が出力する各記述は、データパックの名前、バージョンの番号 (取得元が Modrinth でなければ、mism は `-` を出力する)、データパックのファイルの SHA-256、取得元の指定 (dp-4 の形)をこの順に並べたものである。dfetch-4 で取得元の指定を置き換えたファイルについて、mism は、置き換えた後の取得元の指定とバージョンの番号を出力する。

### 削除 (remove)

- drm-1. 利用者が `mism datapack remove <データパックの名前>` を実行したとき、mism は、対象のサーバーのワールドのディレクトリの `datapacks/` から `mism.toml` の記録にあるデータパックのファイルを削除し、`mism.toml` からそのデータパックの記録を削除し、終了ステータス 0 で終了する。mism は、ワールドのディレクトリの中の、データパックのファイル以外のファイルとディレクトリを削除しない。
- drm-2. 利用者が与えた <データパックの名前> の記録が `mism.toml` に無いとき、mism は、処理を中止してエラーを報告し、ワールドのディレクトリと `mism.toml` を変えない。
- drm-3. `mism.toml` の記録にあるデータパックのファイルが `datapacks/` に無いとき、mism は、その旨を標準出力に出力し、記録だけを削除して終了ステータス 0 で終了する。
