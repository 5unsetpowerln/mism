## 対象範囲

mism は、Minecraft のサーバーを管理するためのコマンドラインツールである。
この仕様書は、mism の機能のうち、サーバーの新規作成、Minecraft のバージョンの列挙、mism がダウンロードした jar ファイルの再利用のための保存、サーバーの新規作成に伴う利用者の EULA への同意と、mism 自身の出力の規則を定める。
mism が扱うサーバーは、PaperMC が配布している Paper と Folia である。
mism は、Linux の上で動く。

この仕様書の番号付きの文には、節の略号と連番からなる番号 (e.g. `new-3`)が付いている。
各テスト関数は、確かめる番号付きの文の番号を、そのテスト関数の `///` コメントに書く。

PaperMC は、Minecraft の各バージョン (e.g. `26.3`、`1.21.11`)に対して、Paper と Folia を配布している。
PaperMC は、1 つの Minecraft のバージョンに対する Paper (または Folia)に、番号で表したバージョン (e.g. `206`)を付け、そのバージョンごとに jar ファイルを配布している。
PaperMC は、Minecraft の各バージョンに、サポート状態 (SUPPORTED、DEPRECATED、UNSUPPORTED のいずれか)を付けて公開している。

## コマンドラインの形式

mism は、次の 2 つのサブコマンドを持つ。

```
mism new <paper|folia> <パス> [--version <Minecraft のバージョン>]
mism versions <paper|folia>
```

利用者は、Paper を `paper` という文字列で、Folia を `folia` という文字列で指定する。

- cli-1. 利用者が `mism --help` を実行したとき、mism は、mism の使い方を標準出力に出力し、終了ステータス 0 で終了する。
- cli-2. 利用者が `mism --version` を実行したとき、mism は、mism 自身のバージョンを標準出力に出力し、終了ステータス 0 で終了する。
- cli-3. 利用者が `mism new --help` または `mism versions --help` を実行したとき、mism は、そのサブコマンドの使い方を標準出力に出力し、終了ステータス 0 で終了する。
- cli-4. 利用者が上の形式に合わない引数を与えたとき、mism は、mism の使い方を標準エラー出力に出力し、終了ステータス 2 で終了する。
- cli-5. 利用者が <paper|folia> の位置に `paper` と `folia` 以外の文字列を与えたとき、mism は、cli-4 と同じ動作をする。

## 出力の規則

この節は、すべてのサブコマンドに共通する、mism の出力の規則を定める。
mism の出力は人向けであり、mism は、人向けの出力を標準出力と標準エラー出力に分けない。
mism は、結果を JSON で出力するオプション (`--json`)をまだ持たない。変更を行う者がそのオプションを mism に足すとき、変更を行う者は、機械向けの出力の規則をこの節に足す。

- out-1. mism 自身が標準出力に出力する文字列の各行は、`mism: ` で始まる。cli-1 から cli-4 が定める使い方の出力と、cli-2 が定める mism 自身のバージョンの出力と、out-2 の空行は、この文の対象外である。
- out-2. mism が外部のソフトウェア (e.g. サーバー)を起動してその出力を利用者に見せるとき、mism は、標準出力に、何の出力が続くかを伝える `mism: ` で始まる 1 行の文字列 (e.g. `mism: output of paper-26.3-206.jar follows`)、空行 1 行、その外部のソフトウェアの標準出力と標準エラー出力の内容 (mism は、その内容を書き換えず、その内容の各行に接頭辞も付けない)、空行 1 行、何の出力が終わったかを伝える `mism: ` で始まる 1 行の文字列 (e.g. `mism: output of paper-26.3-206.jar ended`)を、この順に出力する。
- out-3. mism の標準出力が端末であるとき、out-2 が定める、外部のソフトウェアの出力の始まりと終わりを伝える 2 つの文字列の先頭の `mism` は青色で出力され、その文字列の残りには色が付かない。標準出力が端末でないとき、mism は、色の指定 (エスケープシーケンス)を出力しない。
- out-4. mism 自身は、標準エラー出力に何も出力しない。cli-4 と cli-5 が定める使い方の出力は、この文の対象外である。

## サーバーの新規作成

### バージョンの選択

- sel-1. 利用者が `--version` を省略したとき、mism は、PaperMC がサポート状態 SUPPORTED を付けている Minecraft のバージョンのうち、最も新しくリリースされたものを選ぶ。
- sel-2. 利用者が `--version` に文字列を指定したとき、mism は、PaperMC が Paper (または Folia)を配布している Minecraft のバージョンのうち、その文字列と完全に一致するものを選ぶ。mism は、指定された文字列を別の表記に変換しない (e.g. `26.03` は `26.3` と一致しない)。
- sel-3. mism は、選んだ Minecraft のバージョンに対して PaperMC が配布している Paper (または Folia)のバージョンのうち、番号が最も大きいものを選ぶ。

### 作成の結果

Paper と Folia は、起動したディレクトリに `eula.txt` が無い状態で起動すると、そのディレクトリに `server.properties` と `eula=false` を書いた `eula.txt` を生成して終了し、ワールドを生成しない。
mism は、この動作を使って、利用者がサーバーを本格的に起動する前に、`server.properties` と `eula.txt` を用意する。

- new-1. 利用者が <パス> に相対パスを与えたとき、mism は、その相対パスを、カレントディレクトリを基準にした絶対パスとして扱う。
- new-2. `mism new` が成功したとき、<パス> はディレクトリである。
- new-3. `mism new` が成功したとき、そのディレクトリの直下に、mism が選んだ Paper (または Folia)のバージョンの jar ファイルが、PaperMC が配布している名前 (e.g. `paper-26.3-206.jar`)のまま 1 つある。
- new-4. mism は、jar ファイルを置いた後に、サーバーをそのディレクトリの中で 1 度だけ起動し、サーバーが終了するまで待つ。
- new-5. サーバーが起動している間、mism は、サーバーの標準出力と標準エラー出力の内容を、出力の規則 (out-2)に従って出力する。
- new-6. `mism new` が成功したとき、そのディレクトリの直下の `eula.txt` は、`eula=true` という記述を含み、`eula=false` という記述を含まず、サーバーが書いた他の内容をそのまま含む。
- new-7. mism は、`eula.txt` を書き換える前に、利用者に確認を求めない。利用者は、`mism new` を実行することで Minecraft の EULA に同意したものとする。
- new-8. `mism new` が成功したとき、そのディレクトリの直下に `server.properties` がある。
- new-9. `mism new` が成功したとき、そのディレクトリの直下に `mism.toml` という名前の TOML 形式のファイルがあり、そのファイルは、mism がそのサーバーに Paper と Folia のどちらを使ったか、Minecraft のバージョン、Paper (または Folia)のバージョンの 3 つを記録している。
- new-10. `mism new` が成功したとき、mism は、mism がそのサーバーに使ったのが Paper なら `paper`、Folia なら `folia`、Minecraft のバージョン、Paper (または Folia)のバージョン、作成したディレクトリの絶対パスをこの順に空白 1 文字で区切った記述を、出力の規則に従って標準出力に出力し、終了ステータス 0 で終了する。

### エラー

- err-1. 利用者が指定した <パス> に、ファイル、ディレクトリ、シンボリックリンク (リンク先の無いものを含む)のいずれかが既に存在するとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-2. 利用者が指定した <パス> の親ディレクトリが存在しないとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-3. 利用者が `--version` に指定した文字列と一致する Minecraft のバージョンを PaperMC が配布していないとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-4. 利用者が `--version` を省略し、PaperMC が配布している Minecraft のバージョンの中に PaperMC がサポート状態 SUPPORTED を付けているものが 1 つも無いとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-5. mism が PaperMC との通信に失敗したとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-6. mism がダウンロードした jar ファイルの SHA-256 が、PaperMC が公開している値と一致しないとき、mism は、サーバーの作成を中止してエラーを報告する。
- err-7. サーバーが終了した後に、`eula.txt` と `server.properties` の両方が作成中のディレクトリに揃っていないとき、mism は、サーバーの初回起動の失敗として、サーバーの作成を中止してエラーを報告する。
- err-8. mism がサーバーの作成を中止してエラーを報告したとき、利用者が指定した <パス> には何も存在しない。
- err-9. mism が実行を中止してエラーを報告するとき、mism は、何が失敗したか、その原因、利用者が取れる対処を、出力の規則に従って標準出力に出力し、終了ステータス 1 で終了する。この仕様書は、エラーの出力の長さを定めない。

### 中断

- int-1. `mism new` の実行中に mism が SIGINT (Ctrl-C)または SIGTERM を受けたとき、mism は、起動中のサーバーがあればそれを止め、利用者が指定した <パス> に何も残さずに終了する。

## バージョンの列挙

- ver-1. 利用者が `mism versions paper` (または `mism versions folia`)を実行したとき、mism は、PaperMC が Paper (または Folia)を配布しているすべての Minecraft のバージョンを、リリースが新しい順に、出力の規則に従って 1 つずつ改行で区切って標準出力に出力し、終了ステータス 0 で終了する。
- ver-2. ver-1 で mism が出力する各バージョンの記述は、Minecraft のバージョン、タブ 1 文字、PaperMC がそのバージョンに付けているサポート状態 (SUPPORTED、DEPRECATED、UNSUPPORTED のいずれか)をこの順につないだものである。
- ver-3. mism が PaperMC との通信に失敗したとき、mism は、Minecraft のバージョンを 1 つも出力せず、バージョンの列挙を中止して err-9 と同じ動作をする。

## ダウンロードした jar ファイルの保存

mism は、ダウンロードした jar ファイルを、次に同じ jar ファイルが必要になったときに再利用するために、利用者のホームの下のディレクトリ (以下、この節ではキャッシュのディレクトリと呼ぶ)に保存する。

- cache-1. 環境変数 `XDG_CACHE_HOME` が設定されているとき、キャッシュのディレクトリは `$XDG_CACHE_HOME/mism` である。
- cache-2. 環境変数 `XDG_CACHE_HOME` が設定されていないとき、キャッシュのディレクトリは `~/.cache/mism` である。
- cache-3. mism が選んだ Paper (または Folia)のバージョンの jar ファイルがキャッシュのディレクトリに存在し、その SHA-256 が PaperMC が公開している値と一致するとき、mism は、その jar ファイルをダウンロードしない。
- cache-4. mism が選んだ Paper (または Folia)のバージョンの jar ファイルがキャッシュのディレクトリに存在し、その SHA-256 が PaperMC が公開している値と一致しないとき、mism は、その jar ファイルをダウンロードし直し、キャッシュのディレクトリにある jar ファイルを置き換える。
- cache-5. mism は、ダウンロードした jar ファイルの SHA-256 を PaperMC が公開している値と照合し、一致しないときは err-6 の動作をする。
- cache-6. mism は、キャッシュのディレクトリにある jar ファイルを、利用者の操作なしには削除しない。利用者が `mism new` を別の Minecraft のバージョンで実行した後も、前の Minecraft のバージョンの jar ファイルはキャッシュのディレクトリに残る。
