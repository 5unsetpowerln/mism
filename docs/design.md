## 対象範囲

mmmm は、Rust で実装した 1 つの実行ファイルであり、仕様書 (`docs/spec.md`)が定める振る舞いを Linux の上で実現する。
この設計書は、仕様書のすべての番号付きの文 (`cli-1` から `cache-6` まで)を満たす方法を定める。
この設計書の書き方は、`docs/development-rules.md` の「文書の規則」に従う。
この設計書では、`26.3` のような文字列を Minecraft のバージョンと呼び、PaperMC が 1 つの Minecraft のバージョンに対して番号 (e.g. `206`)を付けて配布する Paper (または Folia)を、その番号で識別して Paper (または Folia)のバージョンと呼ぶ。
この設計書で「筆者」と書くときは、この設計書を書いた者を指す。

## 全体の構成

### ファイルの分け方

```
Cargo.toml
src/
  main.rs                   サブコマンドの振り分け、エラーの出力、終了ステータスの決定
  command_line.rs           clap によるコマンドライン引数の定義
  subcommands/
    mod.rs
    new.rs                  mmmm new の手順の全体
    versions.rs             mmmm versions の手順の全体
  http_client.rs            HTTP の送受信 (JSON の取得と、jar ファイルのストリームでの受信)。User-Agent とタイムアウトもここで決める
  interruption.rs           SIGINT と SIGTERM のハンドラの登録と、受信したシグナルを記録するフラグ
  atomic_fs.rs              書き込みが終わるまで名前を持たないファイルの作成と、既存の名前を上書きしない名前の変更
  minecraft_version.rs      Minecraft のバージョンの解析と、新旧の比較
  papermc.rs                Paper のプロジェクトの名前と、Paper にだけ必要な処理。API の呼び出しは papermc_api を使う
  folia.rs                  Folia のプロジェクトの名前と、Folia にだけ必要な処理。API の呼び出しは papermc_api を使う
  papermc_api/
    mod.rs                  PaperMC の API を呼ぶ処理のトレイトと、HTTP で呼ぶ実装。Paper と Folia で共通
    response.rs             API のレスポンスの JSON に対応する型
    selection.rs            Minecraft のバージョンと Paper (または Folia)のバージョンの選択
  jar_cache.rs              キャッシュのディレクトリの決定と、jar ファイルのキャッシュのディレクトリへの保存と取り出し
  server_directory/
    mod.rs                  サーバーのディレクトリを表す型 (パスと mmmm.toml の内容)
    creation.rs             作業用のディレクトリの作成と、指定されたパスへの配置
    initial_launch.rs       初回起動 (java の起動、終了の待機、eula.txt の書き換え)
    mmmm_toml.rs            mmmm.toml の型と読み書き
tests/                      結合テスト。ファイルの分け方は「テスト」の節で定める
```

ディレクトリを持つモジュールは、`mod.rs` をその入口にする。

### モジュール同士の依存の向き

- `main.rs` は、`command_line.rs`、`interruption.rs`、`subcommands/` に依存する。`main.rs` に依存するモジュールは無い。
- `subcommands/mod.rs` は、`command_line.rs`、`papermc.rs`、`folia.rs` に依存する。`subcommands/new.rs` は、`http_client.rs`、`papermc_api/`、`jar_cache.rs`、`server_directory/` に依存する。`subcommands/versions.rs` は、`http_client.rs`、`papermc_api/`、`minecraft_version.rs` に依存する。`subcommands/` に依存するモジュールは `main.rs` だけである。
- `papermc.rs` と `folia.rs` は、他のモジュールに依存しない。`papermc_api/` は、`http_client.rs` と `minecraft_version.rs` に依存する。
- `jar_cache.rs` は、`http_client.rs` と `atomic_fs.rs` に依存する。`server_directory/creation.rs` は、`atomic_fs.rs` と `server_directory/initial_launch.rs` と `server_directory/mmmm_toml.rs` に依存する。
- `http_client.rs`、`server_directory/initial_launch.rs`、`server_directory/creation.rs` は、中断のフラグを確認するので `interruption.rs` に依存する。エラーに中断の種類 (`interruption.rs` の `Signal`)を持たせるモジュール (`jar_cache.rs`、`papermc_api/`、`subcommands/`)も、`interruption.rs` に依存する。
- `interruption.rs`、`atomic_fs.rs`、`minecraft_version.rs` は、他のモジュールに依存しない。

### 複数のモジュールに制約を課す決定

- mmmm は、非同期ランタイムを持たず、mmmm 自身のコードではスレッドを作らず、すべての処理を 1 つのスレッドで順に行う。mmmm の通信は、JSON を返す GET を 2 回と jar ファイルのダウンロードを 1 回行うだけであり、同時に待つ入出力が無いからである。mmmm が ureq に通信の合計の時間の上限を設定すると、ureq は、名前解決のためのスレッドを内部で作る。筆者は、このことを 2026 年 10 月 20 日に確認した。
- 各モジュールは、そのモジュールのエラーの列挙型を thiserror で定義し、そのモジュールのファイルの中に置く。各バリアントは、メッセージに必要な値 (パス、URL、Minecraft のバージョンなど)と、元になったエラーを `#[source]` で持つ。`main.rs` は、各モジュールのエラーを `#[from]` で包む最上位の列挙型を持つ。
- mmmm は、テストのために、mmmm が通常使う値を上書きする環境変数を 2 つ持つ。`MMMM_PAPERMC_URL` は PaperMC の API のベース URL を、`MMMM_DOWNLOAD_IDLE_TIMEOUT` はダウンロードを打ち切るまでの、データが届かない状態が続いてよい秒数を上書きする。この 2 つの環境変数が設定されていなければ、mmmm は本番の値を使う。
- `interruption.rs` は、`SIGINT` と `SIGTERM` のハンドラと、受信したシグナルの種類を記録するプロセス全体で共有するフラグを持つ。`main.rs` は、起動時にそのハンドラを登録する。ハンドラは、フラグにシグナルの種類を記録するだけである。時間のかかる処理 (ダウンロード、Minecraft のサーバーの終了の待機)を行うモジュールは、このフラグを確認し、フラグが立っていれば処理をやめて中断のエラーを返す。

### 追加の機能の置き場所

- 変更を行う者は、新しいサブコマンド (起動、停止、更新、バックアップ)を実装するファイルを、`subcommands/` に 1 つずつ追加する。
- 変更を行う者は、新しいサーバーソフトウェア (e.g. Spigot)を扱うファイル (`spigot.rs`)を `papermc.rs` と同じ階層に追加し、配布元の API を呼ぶモジュールを `spigotmc_api/` のように配布元の名前のディレクトリに置く。複数のサーバーソフトウェアに共通して必要になった型は、変更を行う者が、2 つ目のサーバーソフトウェアを追加する時点で、それらのファイルから共通のモジュールに切り出す。
- 変更を行う者は、プラグインの取得元 (e.g. Modrinth、Hangar)を扱うモジュールを追加するとき、HTTP の送受信に `http_client.rs` を使い、jar ファイルの保存に `jar_cache.rs` を使う。
- 変更を行う者は、サーバーのプロセスの起動と停止、`server.properties` の編集、プラグインの管理を実装するファイルを、`server_directory/` に追加する。

## 依存するクレート

- mmmm は、clap を、コマンドライン引数の定義と解析に使う。筆者が clap を選んだのは、clap が、形式に合わない引数で使い方を標準エラー出力に出して終了ステータス 2 で終わる動作 (cli-4)を持ち、mmmm がそれをそのまま使えるからである。
- mmmm は、ureq を、HTTP の送受信に使う。筆者が ureq を選んだのは、ureq が同期のクライアントなので非同期ランタイムを持たないという決定に合い、ureq が TLS に rustls を使うので OpenSSL のライブラリが無い環境でも mmmm が動き、ureq がレスポンスの本文をストリームとして読めるので mmmm がダウンロードしながら SHA-256 を計算できるからである。
- mmmm は、serde と serde_json を、API のレスポンスの JSON を型に読み込むために使う。筆者がこの 2 つを選んだのは、serde と serde_json が、Rust で JSON を構造体に対応させる方法として定着しているからである。
- mmmm は、toml を、`mmmm.toml` の読み書きに使う。筆者が toml を選んだのは、toml が、serde と組み合わせて構造体と TOML を対応させられるからである。
- mmmm は、sha2 を、jar ファイルの SHA-256 の計算に使う。筆者が sha2 を選んだのは、RustCrypto が sha2 を保守しており、mmmm が jar ファイルをストリームで読みながら SHA-256 を計算できるからである。
- mmmm は、thiserror を、各モジュールのエラーの列挙型の定義に使う。筆者が thiserror を選んだのは、thiserror を使うと、mmmm が `#[source]` と `#[from]` で原因の連鎖を型に持たせられるからである。
- mmmm は、nix を、名前を持たないファイルの作成 (`O_TMPFILE`)、そのファイルへの名前の付与 (`linkat`)、既存の名前を上書きしないディレクトリの名前の変更 (`renameat2`)、Minecraft のサーバーのプロセスへのシグナルの送信に使う。筆者が nix を選んだのは、nix が生の libc の関数に型の付いた安全なラッパーを提供し、mmmm が `unsafe` を書かずに済むからである。Minecraft のサーバーのプロセスのプロセスグループの設定には、mmmm は、標準ライブラリの `CommandExt::process_group` を使う。
- mmmm は、signal-hook を、`SIGINT` と `SIGTERM` のハンドラの登録に使う。筆者が signal-hook を選んだのは、nix のハンドラを登録する関数 (`sigaction`)が `unsafe` であり、signal-hook は、フラグに値を記録するだけのハンドラを `unsafe` を書かずに登録できるからである。
- テストは、wiremock を、テストの中でローカルに立てる偽の HTTP サーバーに使う。筆者が wiremock を選んだのは、wiremock が、テストごとに HTTP サーバーを立てて決まったレスポンスを返す用途に作られているからである。
- テストは、tokio を、wiremock が必要とする非同期ランタイムとして使う。筆者が tokio を選んだのは、wiremock が tokio の上でだけ動くからである。mmmm の実行ファイルは、tokio に依存しない。
- テストは、tempfile を、各テストの一時ディレクトリの作成と、テストの終了時の削除に使う。筆者が tempfile を選んだのは、tempfile を使うと、テストを書く者が一時ディレクトリを削除する処理を各テストに書かずに済むからである。

筆者は、各クレートが `docs/development-rules.md` の「依存するクレートの追加の規則」の 3 番目 (そのクレートに依存しているクレートの数と直近のリリース)を満たすかを、確認していない。

## コマンドラインとエラーの出力

### 責務

`command_line.rs` は、コマンドラインの形を定め、`main.rs` は、サブコマンドの振り分け、エラーの出力、終了ステータスの決定を行う。
この 2 つのファイルは、仕様書の cli-1 から cli-5、err-9、new-10 の終了ステータス、ver-1 の終了ステータスを満たす。

### 方法

mmmm は、clap の derive マクロで、`new` と `versions` の 2 つのサブコマンドと、それぞれの引数を定義する。
mmmm は、利用者が <paper|folia> の位置に与えた引数を clap から文字列のまま受け取り、clap がコマンドラインを解析した後に、その文字列が `paper` と `folia` のどちらかであることを確かめる。どちらでもなければ、mmmm は、利用者が実行したサブコマンドの使い方を含む clap のエラーを標準エラー出力に出力し、終了ステータス 2 で終了する (cli-5)。
mmmm は、形式に合わない引数、`--help`、`--version` に対して、clap の既定の動作をそのまま使う (cli-1 から cli-4)。

`main.rs` は、サブコマンドが返したエラーを、次の形で標準エラー出力に出力し、終了ステータス 1 で終了する (err-9)。

```
mmmm: failed to create directory /home/sunset/servers/survival
  caused by: Permission denied (os error 13)
hint: check that you have write permission to /home/sunset/servers
```

エラーの出力の先頭は、mmmm が何をしようとして失敗したかである。
`caused by:` で始まる各出力は、`Error::source()` をたどって得た原因を、外側から順に 1 つずつ書いたものである。
`hint:` で始まる出力は、利用者が取れる対処であり、エラーの列挙型のバリアントのうち対処が決まっているものだけがこの出力を持つ。
対処が決まっているのは、次の場合である。

- PaperMC が Minecraft のバージョンを配布していない場合 (err-3)、mmmm は、`mmmm versions` で配布しているバージョンを見るよう利用者に案内する。
- Java が見つからない場合と Java が古い場合、mmmm は、必要な Java のバージョンとインストールを利用者に案内する。
- 初回起動が失敗した場合 (err-7)、mmmm は、上に出力されたサーバーのログを見るよう利用者に案内する。
- 通信に失敗した場合 (err-5)、mmmm は、ネットワークの接続を確認するよう利用者に案内する。

変更を行う者は、エラーのメッセージを英語で書く。
mmmm は、中断による終了の終了ステータスを、`SIGINT` のとき 130、`SIGTERM` のとき 143 にする。

### 性質

- d-cli-1. mmmm がエラーを報告したとき、エラーの報告の最初の行は `mmmm: ` で始まる。標準エラー出力の中で、サーバーの出力 (new-5)がエラーの報告の前にあることはあるが、サーバーの出力の行が `mmmm: ` で始まることはない。
- d-cli-2. エラーに原因のエラーがあるとき、標準エラー出力には、`Error::source()` をたどって得られる原因のエラーの数と同じ数だけ、`  caused by: ` で始まる行がある。

### 判断

- 変更を行う者がエラーのメッセージを英語で書くのは、サーバーのログと Java のメッセージが英語であり、利用者が 1 つの端末で読む文の言語を揃えるためである。
- mmmm が終了ステータスを `SIGINT` のとき 130 に、`SIGTERM` のとき 143 にするのは、シェルの慣習 (128 にシグナルの番号を足す)に合わせるためである。
- mmmm が `paper` と `folia` を clap の列挙型 (`ValueEnum`)として定義しないのは、clap 4.6 が、列挙型に無い値のエラーに使い方を含めないからである。筆者は、このことを 2026 年 10 月 20 日に確認した。

## HTTP クライアント

### 責務

`http_client.rs` は、JSON の取得と jar ファイルのストリームでの受信を行い、User-Agent ヘッダーとタイムアウトを決める。
このモジュールは、仕様書の err-5 の検出を担う。

### 方法

mmmm は、すべてのリクエストに `mmmm/<mmmm のバージョン> (me@5unset.me)` という User-Agent ヘッダーを付ける。

mmmm は、接続の確立に 10 秒を超えた場合と、JSON のレスポンスの受信に合計で 30 秒を超えた場合に、通信が失敗したとみなす。
mmmm は、jar ファイルのダウンロードには合計の時間の上限を設けず、データが 30 秒間まったく届かない場合にだけ失敗とみなす。
テストは、この 30 秒を環境変数 `MMMM_DOWNLOAD_IDLE_TIMEOUT` で上書きできる。

mmmm は、HTTP ステータスが 200 ではないレスポンスを、取得の失敗として扱う。
取得の失敗を伝えるエラーは、リクエストした URL と HTTP ステータスを含め、レスポンスの JSON が `message` フィールドを持つ場合はその文字列も含める。

mmmm は、jar ファイルのダウンロードの間、ストリームからまとまったバイト列を 1 回読むたびに中断のフラグを確認し、フラグが立っていればダウンロードをやめる。

### 性質

- d-http-1. jar ファイルのダウンロード中にデータが届かない状態が 30 秒 (または `MMMM_DOWNLOAD_IDLE_TIMEOUT` の秒数)続いたとき、mmmm は、通信の失敗としてダウンロードを中止してエラーを報告する。
- d-http-2. jar ファイルのダウンロードが遅くても進んでいるとき、mmmm は、時間を理由にダウンロードを打ち切らない。

### 判断

- mmmm がこの User-Agent ヘッダーを付けるのは、PaperMC のドキュメントが、ソフトウェアの名前と連絡先を含む User-Agent ヘッダーを求めているからである。
- mmmm がダウンロードに合計の時間の上限を設けないのは、回線が遅いだけで進んでいるダウンロードを打ち切らないためである (e.g. mmmm が 55 MB の jar ファイルを 80 KB/s で受信すると、受信に約 11 分かかる)。mmmm が止まった接続だけを検出するには、mmmm がデータの届かない時間で判定すれば足りる。
- 筆者は、ureq 3.4.2 の設定に、データが届かない時間によるタイムアウトが無いことを、2026 年 10 月 20 日に確認した。設定にあるのは、接続、ヘッダーの受信、本文の受信のそれぞれにかかる合計の時間の上限だけである。そのため、mmmm は、ureq の `unversioned::transport` モジュールの API で接続をラップし、ソケットから 1 回読むたびの待ち時間に上限を付けて、データが届かない時間によるタイムアウトを実現する。このモジュールの API は semver の対象外なので、変更を行う者は、Cargo.toml で ureq のバージョンをマイナーバージョンまで固定する。
- mmmm が HTTPS でダウンロードしている間に `SIGINT` または `SIGTERM` を受けたとき、データが届いていれば、mmmm は、次にデータを読んだ時点で中断に気付く。データが届いていなければ、rustls が、シグナルで中断された読み取り (`EINTR`)を内部でやり直すので、mmmm は、データが届かない時間の上限 (30 秒)が過ぎた時点で中断に気付く。筆者は、このことを 2026 年 10 月 20 日に確認した。

## Minecraft のバージョンの新旧の判定

### 責務

`minecraft_version.rs` は、Minecraft のバージョンを解析し、2 つの Minecraft のバージョンのどちらが新しくリリースされたかを決める。
このモジュールは、仕様書の sel-1 と ver-1 の「リリースが新しい順」の判定を担う。

### 方法

PaperMC の API は、Minecraft のバージョンを PaperMC に登録された日時の新しい順に返すが、API のドキュメントはその順序を保証していない。
そのため、mmmm は、どちらが新しくリリースされたかを、Minecraft のバージョンの解析によって決める。

mmmm は、Minecraft のバージョンを、数の並びと接尾辞に分けて解析する。
数の並びは、1 つ以上の非負整数を `.` でつないだものである (e.g. `26.3` の数の並びは `[26, 3]`、`1.21.11` の数の並びは `[1, 21, 11]`)。
接尾辞は、次の 3 つのどれかである。

- 接尾辞が無い Minecraft のバージョン (e.g. `26.3`、`26.1.2`、`1.21.11`)は、正式リリースを表す。
- `-pre<数>` または `-pre-<数>` の接尾辞を持つ Minecraft のバージョン (e.g. `1.21.11-pre5`、`26.1-pre-1`)は、プレリリースを表す。
- `-rc<数>` または `-rc-<数>` の接尾辞を持つ Minecraft のバージョン (e.g. `1.21.11-rc3`、`26.3-rc-3`)は、リリース候補を表す。

mmmm は、2 つの Minecraft のバージョンを次の順で決着が付くまで比べる。

1. mmmm は、数の並びを先頭から 1 つずつ整数として比べる。数の並びの長さが違うときは、mmmm は、短い方の足りない部分を 0 とみなす。
2. 数の並びが等しければ、mmmm は、接尾辞の種類で比べ、プレリリース、リリース候補、正式リリースの順に新しいとみなす。
3. 接尾辞の種類も等しければ、mmmm は、接尾辞の数が大きい方を新しいとみなす。

どの形にも当てはまらない Minecraft のバージョンを API が返した場合、mmmm は、そのバージョンの文字列を含むエラーを報告する。

### 性質

- d-ver-1. mmmm が `26.1` と `26.1.2` を比べたとき、`26.1.2` が新しい。
- d-ver-2. mmmm が `26.3-rc-3` と `26.3` を比べたとき、`26.3` が新しい。
- d-ver-3. mmmm が `1.21.11-pre5` と `1.21.11-pre6` を比べたとき、`1.21.11-pre6` が新しい。
- d-ver-4. mmmm が `1.21.11-rc3`、`1.21.11`、`26.1.2`、`26.3-rc-3`、`26.3` を並べたとき、この順が古い順である。
- d-ver-5. mmmm が 3 つの形のどれにも当てはまらない文字列 (e.g. `26.3-snapshot`)を解析したとき、mmmm は、その文字列を含むエラーを報告する。

### 判断

- 筆者は、3 つの形を、2026 年 10 月 20 日に API が返した実際の Minecraft のバージョンから取った。Minecraft は 2026 年のリリースからバージョンの形を変えたので、PaperMC は `-rc3` と `-rc-3` のような 2 つの形を両方とも配布している。
- mmmm が接尾辞の順序をプレリリース、リリース候補、正式リリースとするのは、Minecraft がこの順に出すからである。

## PaperMC の API

### 責務

`papermc_api/` は、PaperMC の API を呼び、Minecraft のバージョンと Paper (または Folia)のバージョンを選ぶ。
`papermc.rs` と `folia.rs` は、API のパスに入れるプロジェクトの名前 (`paper`、`folia`)を持つ。Paper にだけ必要な処理と Folia にだけ必要な処理は、今は無い。
これらのモジュールは、仕様書の sel-1 から sel-3、err-3、err-4、err-5、ver-1、ver-2 を満たす。

### 方法

mmmm は、PaperMC がダウンロードのために提供している API のバージョン 3 (ベース URL `https://fill.papermc.io/v3`)を使う。
環境変数 `MMMM_PAPERMC_URL` が設定されているとき、mmmm は、その値をベース URL として使う。

PaperMC の API は、Paper (または Folia)のバージョンを `build` という名前で呼ぶ。
mmmm は、その名前を URL と JSON のフィールド名としてそのまま使うが、変更を行う者は、コードと文書の中ではそれを Paper (または Folia)のバージョンと呼ぶ。

mmmm は、次の 2 つのエンドポイントだけを使う。

バージョンの一覧のエンドポイントは、`GET /v3/projects/{paper|folia}/versions` である。
mmmm は、このレスポンスの `versions` の各要素から、`version.id` (Minecraft のバージョン)、`version.support.status` (サポート状態)、`builds` (Paper (または Folia)のバージョンの配列)、`version.java.version.minimum` (必要な Java の最小のバージョン)を読む。

ダウンロードの情報のエンドポイントは、`GET /v3/projects/{paper|folia}/versions/{Minecraft のバージョン}/builds/{Paper (または Folia)のバージョン}` である。
mmmm は、このレスポンスの `downloads` の `server:default` が持つ `name` (jar ファイルの名前)、`checksums.sha256`、`url` を読む。
mmmm は、jar ファイルを `url` が示す URL からダウンロードし、jar ファイルの URL を文字列をつないで作ることはしない。

`papermc_api/mod.rs` は、API を呼ぶ処理をトレイトとして定義する。
トレイトは、「Minecraft のバージョンの一覧を得る」と「1 つの Paper (または Folia)のバージョンのダウンロードの情報を得る」の 2 つの操作を持つ。
HTTP で呼ぶ実装は、`http_client.rs` を使う。

`papermc_api/selection.rs` は、Minecraft のバージョンと Paper (または Folia)のバージョンを、次の手順で選ぶ。

利用者が `--version` を指定した場合、mmmm は、次の手順で選ぶ。

1. mmmm は、バージョンの一覧のエンドポイントから、Minecraft のバージョンの一覧を得る。
2. 一覧の中に `version.id` が利用者の指定した文字列と一致する要素が無ければ、mmmm は、サーバーの作成を中止してエラーを報告する (err-3)。mmmm は、一覧と照合した後の文字列だけを URL に入れる。
3. mmmm は、その要素の `builds` の最大値を Paper (または Folia)のバージョンとする (sel-3)。

利用者が `--version` を省略した場合、mmmm は、次の手順で選ぶ。

1. mmmm は、バージョンの一覧のエンドポイントから得た一覧を、`version.id` のリリースが新しい順に並べる。
2. mmmm は、並べた順に見て、`version.support.status` が `SUPPORTED` である最初の要素を選ぶ (sel-1)。1 つも無ければ、mmmm は、サーバーの作成を中止してエラーを報告する (err-4)。
3. mmmm は、その要素の `builds` の最大値を Paper (または Folia)のバージョンとする (sel-3)。

mmmm が選んだ要素の `builds` が空の配列である場合、mmmm は、その Minecraft のバージョンの Paper (または Folia)が配布されていないことを伝えるエラーを報告する。

どちらの場合も、その後に mmmm は、ダウンロードの情報のエンドポイントから jar ファイルの名前、SHA-256、URL を得る。

### 性質

- d-api-1. `mmmm new` は、API を 2 回だけ呼ぶ。
- d-api-2. mmmm が URL に入れる Minecraft のバージョンの文字列は、バージョンの一覧のエンドポイントが返した `version.id` のどれかである。
- d-api-3. バージョンの一覧のエンドポイントが返した順序と、リリースが新しい順が食い違うとき、mmmm は、リリースが新しい順に従って選ぶ。

### 判断

- 筆者は、バージョンの一覧のエンドポイントがすべての Minecraft のバージョンとそのサポート状態を 1 回で返すことを、2026 年 10 月 20 日に確認した。筆者は、このレスポンスの各要素が持つキーが `builds`、`version.id`、`version.support.status`、`version.support.end`、`version.java.version.minimum`、`version.java.flags.recommended` であることも、同じ日に確認した。
- 筆者は、ダウンロードの情報のエンドポイントが存在し、そのレスポンスが `id`、`channel`、`time`、`downloads` を持ち、`downloads` の `server:default` が `name`、`checksums.sha256`、`url` を持つことを、Paper (`26.3` の `206`)と Folia (`26.3` の `3`)について 2026 年 10 月 20 日に確認した。存在しない Minecraft のバージョンや Paper (または Folia)のバージョンを URL に入れると、この API は、HTTP ステータス 404 と、`ok`、`error`、`message` の 3 つのキーを持つ JSON を返す。筆者は、この応答を同じ日に確認した。
- 旧バージョンの API (`https://api.papermc.io/v2`)は、2026 年 7 月 1 日に廃止されており、HTTP ステータス 410 を返す。筆者は、この HTTP ステータスを 2026 年 10 月 20 日に確認した。
- 筆者が API を呼ぶ処理をトレイトにするのは、Minecraft のバージョンと Paper (または Folia)のバージョンを選ぶ手順を、通信なしで単体テストするためである。
- 筆者は、`builds` が空の配列になり得るかを、確認していない。2026 年 10 月 20 日にバージョンの一覧のエンドポイントが返した Paper の 68 個と Folia の 13 個の Minecraft のバージョンには、`builds` が空のものは無かった。仕様書には、この場合の番号付きの文が無い。

## 書き込みが終わるまで名前を持たないファイルの操作

### 責務

`atomic_fs.rs` は、書き込みが終わるまで名前を持たないファイルの作成と、既存の名前を上書きしない名前の変更を提供する。
このモジュールは、`jar_cache.rs` と `server_directory/creation.rs` が使う。

### 方法

mmmm は、名前を持たないファイルを、置く予定のディレクトリの中に `O_TMPFILE` で作る。
このファイルは、名前を付けるまでディレクトリの一覧に現れず、mmmm がどのように終了してもカーネルが解放する。
mmmm は、書き込みが終わったファイルに `linkat` で名前を付ける。
`O_TMPFILE` に対応していないファイルシステムでは、mmmm は、ファイルの作成を中止してエラーを報告する。

mmmm は、ディレクトリの名前の変更に `renameat2` の `RENAME_NOREPLACE` を使い、変更先に既に何かあれば失敗させる。

### 性質

- d-fs-1. 名前を付ける操作の前に mmmm がどのように終了しても、ディレクトリに名前を持つファイルは増えない。
- d-fs-2. 名前を付ける操作の前後で、他のプロセスから見ると、名前を付ける先のパスのファイルは「無い」か「書き込みが終わっている」のどちらかにしか見えない。

### 判断

- mmmm が、`O_TMPFILE` に対応していないファイルシステムで、名前を持つ一時ファイルを作ってから名前を変えるような別の方法に切り替えないのは、開発のルールのフォールバックをしないという規則による。ext4、XFS、Btrfs、tmpfs は `O_TMPFILE` に対応している。
- 筆者は、`renameat2` の `RENAME_NOREPLACE` が使えるカーネルのバージョンを、確認していない。
- Rust のクレートの nix 0.31 は、`renameat2` を glibc 向けにだけ提供しているので、変更を行う者は、mmmm を musl 向けにはビルドできない。筆者は、このことを 2026 年 10 月 20 日に確認した。

## jar ファイルのキャッシュ

### 責務

`jar_cache.rs` は、mmmm が選んだ Paper (または Folia)のバージョンの jar ファイルを、キャッシュのディレクトリから取り出すか、ダウンロードしてキャッシュのディレクトリに保存する。
このモジュールは、仕様書の cache-1 から cache-6 と err-6 を満たす。

### 方法

キャッシュのディレクトリの中の jar ファイルのパスは、`<キャッシュのディレクトリ>/<paper|folia>/<Minecraft のバージョン>/<Paper (または Folia)のバージョン>/<jar ファイルの名前>` である (e.g. `~/.cache/mmmm/paper/26.3/206/paper-26.3-206.jar`)。
キャッシュのディレクトリは、環境変数 `XDG_CACHE_HOME` が設定されていればその中の `mmmm`、未設定なら `~/.cache/mmmm` である (cache-1、cache-2)。

1. そのパスにファイルがあれば、mmmm は、それを読みながら SHA-256 を計算し、計算した SHA-256 が API の値と一致すればそのファイルをそのまま使う (cache-3)。計算した SHA-256 が一致しなければ、mmmm は、手順 2 に進む (cache-4)。
2. mmmm は、同じディレクトリの中に、名前を持たないファイルを作る。
3. mmmm は、受信した内容をそのファイルに書きながら SHA-256 を計算する。
4. 計算した SHA-256 が API の値と一致しなければ、mmmm は、そのファイルを閉じ、サーバーの作成を中止してエラーを報告する (err-6)。
5. 一致すれば、mmmm は、手順 1 で一致しなかったファイルがあればそれを削除し、名前を持たないファイルに、この節の冒頭で定めた jar ファイルのパスの名前を付ける。
6. 手順 5 で「その名前は既にある」という理由で名前を付けられなかった場合、mmmm は、mmmm が作った名前を持たないファイルを閉じ、既にあるファイルを手順 1 と同じ方法で照合して使う。

mmmm は、キャッシュのディレクトリにある jar ファイルを、利用者の操作なしには削除しない (cache-6)。

### 性質

- d-cache-1. ダウンロードの途中で mmmm がどのように終了しても、キャッシュのディレクトリに名前を持つファイルは増えない。
- d-cache-2. キャッシュのディレクトリの中の jar ファイルのパスにファイルが存在するとき、そのファイルは、書き込みが終わり、SHA-256 の照合を 1 度は通っている。
- d-cache-3. 同じ jar ファイルを 2 つの mmmm が同時にダウンロードしたとき、両方が成功し、そのパスにはファイルが 1 つだけ存在する。

### 判断

- mmmm が jar ファイルの内容を名前を持たないファイルに書くのは、途中で止まったファイルがそのパスに残ると、次回の mmmm がそれを完成したファイルとして読んでしまうからである。
- mmmm が名前を持たないファイルをキャッシュのディレクトリと同じディレクトリに作るのは、名前を付ける操作が同じファイルシステムの中でしか成り立たないからである。
- mmmm が名前を付ける前に SHA-256 を API の値と照合するので、d-cache-2 が成り立つ。これは、キャッシュのディレクトリから読む側が照合する cache-3 とは別の保証である。

## mmmm new の手順と中断

### 責務

`subcommands/new.rs` は、`mmmm new` の手順の全体を担い、`server_directory/creation.rs` は、利用者が指定した <パス> の検査、作業用のディレクトリの作成、<パス> への配置を担う。
利用者が mmmm を中断したとき、mmmm は、起動中のサーバーを止め、<パス> に何も残さない。
この 2 つのモジュールは、仕様書の new-1、new-2、new-10、err-1、err-2、err-8、int-1 を満たす。

### 方法

mmmm は、サーバーの準備を、<パス> の隣に作った作業用のディレクトリの中で行い、すべて終わってからそのディレクトリの名前を <パス> に変える。

1. <パス> が相対パスなら、mmmm は、カレントディレクトリをつないで絶対パスにする (new-1)。
2. mmmm は、<パス> をシンボリックリンクをたどらずに調べ (`lstat`)、ファイル、ディレクトリ、シンボリックリンクのどれかがあれば、サーバーの作成を中止してエラーを報告する (err-1)。
3. <パス> の親ディレクトリが無い場合と、親ディレクトリのパスにディレクトリ以外のものがある場合、mmmm は、サーバーの作成を中止してエラーを報告する (err-2)。
4. mmmm は、Minecraft のバージョンと Paper (または Folia)のバージョンを選び、jar ファイルをキャッシュのディレクトリに用意する。
5. mmmm は、親ディレクトリの中に `.mmmm-tmp-<16 桁のランダムな 16 進数>` という名前の作業用のディレクトリを作る。
6. mmmm は、キャッシュのディレクトリの jar ファイルを作業用のディレクトリに複製し、複製した内容の SHA-256 を API の値と照合する。
7. mmmm は、作業用のディレクトリの中でサーバーを初回起動し、`eula.txt` を書き換え、`mmmm.toml` を作る (「初回起動」の節)。
8. mmmm は、作業用のディレクトリの名前を <パス> に変える。<パス> に既に何かあれば名前の変更は失敗し、mmmm は、サーバーの作成を中止してエラーを報告する。
9. mmmm は、`paper` か `folia`、Minecraft のバージョン、Paper (または Folia)のバージョン、<パス> をこの順に空白 1 文字で区切り、改行で終えた文字列を標準出力に出力する (new-10)。

手順 5 から 8 のどこかで mmmm がエラーを報告する場合、mmmm は、作業用のディレクトリを中身ごと削除する (err-8)。

mmmm は、中断を次のとおり扱う (int-1)。

- mmmm は、サーバーのプロセスを mmmm とは別のプロセスグループで起動する。
- mmmm は、サーバーの終了を待つ間、100 ミリ秒ごとに中断のフラグを確認する。フラグが立っていたら、mmmm は、サーバーのプロセスに `SIGTERM` を送り、サーバーのプロセスが 10 秒以内に終了しなければ `SIGKILL` を送る。
- サーバーが終了した後、mmmm は、作業用のディレクトリを中身ごと削除し、サーバーの作成が中断されたことを標準エラー出力に出力して、終了ステータス 130 (`SIGINT`)または 143 (`SIGTERM`)で終了する。
- mmmm は、ダウンロードの間の中断を、`http_client.rs` がフラグを確認することで扱う。
- mmmm は、手順 8 の名前の変更の直前にもフラグを確認し、フラグが立っていれば、名前を変えずに作業用のディレクトリを削除して中断として終了する。mmmm が名前の変更の直前にもフラグを確認するのは、サーバーの終了から名前の変更までの間に mmmm が受けたシグナルで、完成したディレクトリが <パス> に残らないようにするためである。

### 性質

- d-new-1. `mmmm new` のどの時点で失敗や中断が起きても、<パス> にディレクトリが存在するのは、準備がすべて終わった後だけである。
- d-new-2. <パス> の検査の後に別のプロセスが <パス> に何かを作ったとき、名前の変更は失敗し、mmmm は、エラーを報告して作業用のディレクトリを削除する。
- d-new-3. 中断のとき、サーバーのプロセスは、mmmm が終了する前に終了している。
- d-new-4. mmmm が `SIGKILL` で止められたとき、<パス> には何も存在しないが、親ディレクトリに `.mmmm-tmp-` で始まるディレクトリが残ることがある。
- d-new-5. mmmm は <パス> の検査 (手順 1 から 3)を通信より先に行うので、通信の失敗で作業用のディレクトリが残ることはない。

### 判断

- mmmm が作業用のディレクトリを <パス> の隣に作るのは、名前の変更が同じファイルシステムの中でしか成り立たないからである。mmmm が作業用のディレクトリを `/tmp` や `~/.local/share/mmmm` に作ると、<パス> が別のファイルシステムにある場合に複製が必要になり、複製の途中の状態が <パス> に現れる。
- mmmm が `lstat` を使うのは、`stat` がリンク先の無いシンボリックリンクを「存在しない」と報告するからである。
- mmmm がサーバーを別のプロセスグループで起動するのは、端末の Ctrl-C がフォアグラウンドのプロセスグループ全体に `SIGINT` を送るからである。mmmm がサーバーのプロセスを mmmm と同じグループにすると、サーバーが mmmm より先に `SIGINT` を受けて独自の終了処理を始め、mmmm が止める順序を制御できない。
- mmmm が `SIGTERM` の後に 10 秒待ってから `SIGKILL` を送るのは、サーバーに自身の終了処理の機会を与えつつ、無限には待たないためである。初回起動の段階ではワールドが無く終了が速いので、筆者は 10 秒を十分とみなしたが、筆者はそれを確認していない。

## 初回起動

### 責務

`server_directory/initial_launch.rs` は、作業用のディレクトリの中でサーバーを 1 度起動し、終了を待ち、`eula.txt` を書き換える。
このモジュールは、仕様書の new-3 から new-8 と err-7 を満たす。

### 方法

Paper と Folia は、起動したディレクトリに `eula.txt` が無い状態で起動すると、そのディレクトリに `server.properties` と `eula=false` を書いた `eula.txt` を生成して終了し、ワールドを生成しない。
mmmm は、この動作を使い、サーバーの終了ステータスには頼らず、サーバーの終了後に `eula.txt` と `server.properties` が生成されているかで成否を決める。

1. mmmm は、環境変数 `PATH` の要素のうち絶対パスであるものを順に見て、実行できる `java` を探す。空の要素と相対パスの要素は、mmmm は、見ない。`java` が無ければ、mmmm は、Java が見つからないことを伝えるエラーを報告する。
2. mmmm は、`java -version` を実行して Java のメジャーバージョンを読み取り、それがバージョンの一覧のエンドポイント (`GET /v3/projects/{paper|folia}/versions`)が返す JSON の `version.java.version.minimum` より小さければ、必要な Java のバージョンと見つかった Java のバージョンを伝えるエラーを報告する。`java -version` が終わった後、mmmm は、中断のフラグを確認し、フラグが立っていれば中断として扱う。
3. mmmm は、作業用のディレクトリをカレントディレクトリとして `java -jar <jar ファイルの名前> --nogui` を起動する。mmmm は、サーバーの標準入力を `/dev/null` につなぎ、サーバーの標準出力と標準エラー出力を両方とも mmmm の標準エラー出力につなぐ (new-5)。
4. mmmm は、サーバーの終了を待つ。mmmm は、待つ時間に上限を設けない。
5. サーバーの終了後、作業用のディレクトリに `eula.txt` と `server.properties` の両方があれば、mmmm は初回起動を成功とみなす。どちらかが無ければ、mmmm は、サーバーの作成を中止してエラーを報告する (err-7)。
6. mmmm は、`eula.txt` の中の `eula=false` という記述をすべて `eula=true` に書き換え、他の内容はそのまま残す (new-6)。`eula.txt` に `eula=false` という記述が 1 つも無ければ、mmmm は、サーバーの作成を中止してエラーを報告する。
7. mmmm は、`mmmm.toml` を作業用のディレクトリの直下に書く (new-9)。

### 性質

- d-launch-1. `java` が `PATH` に無いとき、mmmm は、サーバーを起動せずにエラーを報告する。
- d-launch-2. 見つかった Java のメジャーバージョンが必要な最小のバージョンより小さいとき、mmmm は、サーバーを起動せずにエラーを報告する。
- d-launch-3. サーバーが `eula.txt` と `server.properties` を生成せずに終了したとき、mmmm は、エラーを報告する。
- d-launch-4. `eula.txt` の書き換えの前後で、`eula=false` という記述以外の内容は変わらない。

### 判断

- mmmm が初回起動の成否の判定にサーバーの終了ステータスを使わないのは、EULA に未同意のときにサーバーがどの終了ステータスで終わるかを、mmmm が仮定しないためである。
- mmmm が `PATH` の相対パスの要素を見ないのは、mmmm が相対パスの要素を見ると `java` の探索の結果が mmmm のカレントディレクトリに依存し、サーバーは mmmm のカレントディレクトリとは別の作業用のディレクトリで起動されるからである。
- mmmm が `java -version` の後に中断のフラグを確認するのは、`java -version` のプロセスは mmmm と同じプロセスグループにあり、端末の Ctrl-C がそれを止めるので、mmmm が中断のフラグを確認しないと、中断が Java のバージョンの読み取りの失敗として報告されるからである。
- mmmm が `eula=false` の無い `eula.txt` をエラーにするのは、mmmm が初回起動をそのまま成功とみなすと、`eula=true` を含まない `eula.txt` が残り、仕様書の new-6 (`eula.txt` が `eula=true` を含むこと)に反するからである。
- mmmm がサーバーの標準入力を `/dev/null` につなぐのは、サーバーが標準入力からのコンソールの入力を待って止まらないようにするためである。
- 筆者は、`version.java.version.minimum` の意味を、フィールドの名前と観測した値 (Minecraft 26.x の値が 25、1.21.x の値が 21 である。筆者が 2026 年 10 月 20 日に確認した)から判断しており、PaperMC のドキュメントでは確認していない。
- mmmm がサーバーの終了を待つ時間に上限を設けないのは、初回起動が Mojang のサーバー jar の取得を含み、初回起動にかかる時間が回線によって大きく変わるからである。利用者は、Ctrl-C で mmmm を中断できる。

## mmmm.toml

### 責務

`server_directory/mmmm_toml.rs` は、`mmmm.toml` の型と読み書きを担う。
このモジュールは、仕様書の new-9 を満たす。

### 方法

```toml
software = "paper"
minecraft_version = "26.3"
software_version = 206
```

- `software` は、`"paper"` か `"folia"` の文字列である。
- `minecraft_version` は、Minecraft のバージョンの文字列である。
- `software_version` は、その Minecraft のバージョンに対する Paper (または Folia)のバージョンの整数である。

mmmm は、この 3 つのフィールドを持つ構造体を定義し、serde と toml で読み書きする。
読み込み時に、フィールドが欠けている場合、知らないフィールドがある場合、型が合わない場合、mmmm は、ファイルのパスと原因を含むエラーを報告する。

### 判断

- 3 つのキーは、仕様書の new-9 が記録すると定めた 3 つの事実と 1 対 1 で対応する。
- 筆者が `software` と `software_version` を対にするのは、将来 `software = "fabric"` を入れてもキーの名前を変えずに済むようにするためである。
- mmmm が知らないフィールドをエラーにするのは、古い mmmm が新しい `mmmm.toml` を誤って読むことを防ぐためである。

## mmmm versions の手順

### 責務

`subcommands/versions.rs` は、`mmmm versions` の手順の全体を担う。
このモジュールは、仕様書の ver-1 から ver-3 を満たす。

### 方法

1. mmmm は、バージョンの一覧のエンドポイント (`GET /v3/projects/{paper|folia}/versions`)を 1 回呼び、Minecraft のバージョンの一覧を得る。
2. mmmm は、一覧を `version.id` のリリースが新しい順に並べる (ver-1)。
3. mmmm は、各要素について、`version.id`、タブ 1 文字、`version.support.status` の順につないだ文字列を、改行で区切って標準出力に出力する (ver-2)。

呼び出しが失敗した場合、mmmm は、手順 3 に進まないので標準出力に何も出力せず、バージョンの列挙を中止してエラーを報告する (ver-3)。

### 性質

- d-versions-1. `mmmm versions` は、API を 1 回だけ呼ぶ。

## テスト

### 責務

テストは、仕様書のすべての番号付きの文と、設計書のすべての「性質」の見出しの下の番号付きの文 (e.g. `d-cache-1`)が満たされていることを、`cargo test` 1 回で確かめる。
規則は `docs/development-rules.md` の「テストの規則」にあり、この節はその規則を mmmm でどう実現するかを定める。

### 方法

変更を行う者は、`tests/` のファイルを、仕様書の節と同じ分け方 (`command_line.rs`、`new_server.rs`、`versions.rs`、`cache.rs`)で作る。
テストを書く者は、各テスト関数の `///` コメントに、そのテスト関数が確かめる仕様書の番号付きの文の番号か、設計書の「性質」の番号付きの文の番号を書く。

偽の PaperMC は、テストの中で立てるローカルの HTTP サーバー (wiremock)である。
偽の PaperMC は、本物の PaperMC のバージョンの一覧のエンドポイントのレスポンスとして保存したものと、偽の jar ファイル (中身は任意のバイト列で、テストがその SHA-256 を JSON に入れる)を返す。
本物の PaperMC のレスポンスとして保存したものは、`tests/fixtures/` にある。筆者は、Paper と Folia のバージョンの一覧と、Paper `26.3` の `206` と Folia `26.3` の `3` のダウンロードの情報を、2026 年 10 月 20 日に保存した。
wiremock は tokio の上で動くので、各テストは、複数のスレッドを持つ tokio のランタイムを作り、その上で偽の PaperMC を立てる。テストのスレッドが mmmm のプロセスの終了を待って止まっている間も、偽の PaperMC は、ランタイムの別のスレッドで応答する。
wiremock は、HTTP のレスポンスの本文を少しずつ送ることができないので、ダウンロードが遅くても進んでいる場合 (d-http-2)のテストは、テストの中のスレッドで動く小さな TCP サーバーに偽の jar ファイルを返させ、その TCP サーバーに HTTP のレスポンスの本文を間隔を空けて送らせる。
テストは、環境変数 `MMMM_PAPERMC_URL` で偽の PaperMC の URL を mmmm に渡す。

偽の `java` は、シェルスクリプトである。
偽の `java` は、`-version` には決まった出力を返し、`-jar` では `server.properties` と `eula=false` の `eula.txt` を書いて終了する。
テストは、失敗用 (何も書かない)、中断用 (`sleep` する)、古い Java 用 (`-version` が 21 を返す)の 3 種類の別のスクリプトも用意する。
偽の `java` は、起動された回数と引数をファイルに記録し、テストがそれを読む。
テストは、`PATH` の先頭にこのスクリプトを置いたディレクトリを足す。

各テストは、一時ディレクトリを作り、`HOME`、`XDG_CACHE_HOME`、`PATH`、`MMMM_PAPERMC_URL`、`MMMM_DOWNLOAD_IDLE_TIMEOUT` を設定して mmmm の実行ファイルをプロセスとして起動し、標準出力、標準エラー出力、終了ステータス、ディレクトリの中身を確かめる。
テストは、ファイルが現れることやプロセスが終わることを待つとき、期限を決めて、その状態になるまで繰り返し確認する。

変更を行う者は、通信もファイルも使わない処理 (Minecraft のバージョンの新旧の判定、バージョンの選択、`mmmm.toml` の読み書き、`eula.txt` の書き換え)を、そのモジュールのファイルの中の単体テストで確かめる。
バージョンの選択の単体テストでは、テストが、決まった値を返す偽の実装を API のトレイトに与える。

本物の PaperMC に対するテストは、環境変数 `MMMM_TEST_REAL_API=1` のときだけ動く 1 件 (`mmmm versions paper` が成功し、少なくとも 1 つの Minecraft のバージョンを標準出力に出力すること)である。

### 判断

- テストが偽の PaperMC に本物の PaperMC のレスポンスから保存したものを返させるのは、手で書いたデータだと本物と違う形でもテストが通ってしまうからである。
- テストが `java` を `PATH` で差し替えるのは、mmmm が `java` を `PATH` から探すという方法をそのまま使えるので、テストのための環境変数を mmmm の実行ファイルに足さずに済むからである。

## 未決事項

- リポジトリの所有者は、mmmm が選んだ Minecraft のバージョンの `builds` が空の配列である場合の扱いを、仕様書に書いていない。筆者は、`builds` が空になり得るかも確認していない。
- 筆者は、`version.java.version.minimum` の意味を、PaperMC のドキュメントで確認していない。
- 筆者は、mmmm が `SIGTERM` の後に `SIGKILL` を送るまでの 10 秒が十分かを、確認していない。
- 筆者は、`renameat2` の `RENAME_NOREPLACE` が使えるカーネルのバージョンを、確認していない。
- 筆者は、mmmm が依存する各クレートが「依存するクレートの追加の規則」の 3 番目 (そのクレートに依存しているクレートの数と直近のリリース)を満たすかを、確認していない。
- 筆者は、`mmmm versions` が `SIGINT` または `SIGTERM` を受けたときの振る舞いを決めていない。mmmm がハンドラを登録するとシグナルの既定の動作 (終了)がハンドラの動作に置き換わるので、`mmmm versions` は、通信が終わるまで動き続けてから終了する。
- 筆者は、ダウンロードの情報のエンドポイントが返す jar ファイルの名前に `/` や `..` が含まれる場合の扱いを決めていない。今の mmmm は、その名前をそのままファイルの名前に使う。
- 筆者は、中断のときに作業用のディレクトリの削除が失敗した場合に、その失敗をどう伝えるかを決めていない。今の mmmm は、サーバーの作成が中断されたことだけを標準エラー出力に出力する。
- 筆者は、ureq が既定で読むプロキシの環境変数 (`HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`)を mmmm がどう扱うかを決めていない。今の mmmm は、ureq の既定のとおりにそれらを読む。
